# ProGPU WPF Port Architecture

## Porting Definition

Porting means reusing all upstream WPF managed code possible wherever it can reasonably compile and execute: dependency properties, dispatcher/app lifetime, controls, layout, resource lookup, styles/templates, routed input/commands, text objects, XAML/BAML compilation, and theme dictionaries remain WPF-owned. ProGPU and Silk.NET replace the Windows-native rendering, composition, windowing, input, and local OS service boundaries. New work should first try to keep the original WPF managed subsystem on the active path, then add native ProGPU APIs only where the old MIL/DWrite/WIC/Win32/D3D boundary cannot be made portable or where performance-critical GPU execution belongs in ProGPU. Bridge-local compatibility code is temporary unless it preserves a source-level WPF manager path or isolates a native seam for later ProGPU ownership.

Command-source state follows the same rule: `ICommand`, `CanExecute`, `CanExecuteChanged`, `CommandManager.RequerySuggested`, `CommandManager.InvalidateRequerySuggested`, `ButtonBase` command enablement, routed command bindings, input bindings, and command event routing remain WPF-owned. ProGPU receives the resulting visual state and input events; it should not duplicate WPF's command manager, command-source policy, or dispatcher-priority requery behavior.

The compiled-XAML smoke harness now explicitly treats `ResourceDictionary` instance semantics such as `x:Shared="False"`, `System.Xaml.NameScopeDictionary` generic dictionary behavior for standalone and external namescopes, loose `XamlReader.Parse(...)` loading, loose `XamlWriter.Save(...)` Freezable, live `Style`/setter, live `ControlTemplate`, live `DataTemplate`, live `HierarchicalDataTemplate`, live `ItemsPanelTemplate`, live `GroupStyle`, live `FrameworkElement`, and live `FlowDocument` graph round-tripping, Fluent theme dictionary loading, implicit type-key style lookup, popup/tooltip theme resources and owner attachment, `Style.BasedOn` inheritance, `Style.Trigger` property-trigger activation, `Style.Trigger` enter/exit storyboard actions, property-driven `MultiTrigger` enter/exit storyboard actions, binding-driven `DataTrigger` and `MultiDataTrigger` enter/exit storyboard actions, `Style.MultiTrigger` condition evaluation, dynamic style-resource values, `ControlTemplate` visual-state groups, `Window.InputBindings`/`KeyGesture` command metadata, `CommandManager.RequerySuggested` command-source refresh, portable `InputManager` key promotion, `TextCompositionManager`/`TextBox` text editing, `RichTextBox` `EditingCommands` character formatting for toggles, typography variants, font size/family, foreground/background, inline flow direction, paragraph alignment, paragraph flow direction, list marker formatting, list indentation structure editing, list marker removal, table row/column insertion, row/column deletion, and table cell merge/split behind WPF's own table-editing gate, `MouseDevice` capture/release, `ButtonBase.Click` and `RepeatButton` routed click activation, `Slider` routed command/template-thumb drag/value handling, `ScrollBar` routed command/value/`ScrollEvent` handling, `MouseWheel` routed event activation, rich document containers such as `InlineUIContainer`/`BlockUIContainer`, and `DataGrid` row/cell realization including generated text and checkbox cell content as WPF-owned behavior. ProGPU should receive the resulting visuals, brushes, text, normalized native input events, command routing requests, hit-test/vector backend work, and native rendering work, not reimplement those XAML/resource/name-fixup/template/input-binding/command-manager/text-editing/rich-text-command/mouse-routing/range/scrolling/document/grid/theme managers.

Collection-view shaping follows the same reuse rule. Compiled `CollectionViewSource` resources, sort/filter/group descriptions, current-item currency, composite collections, item string formatting, and live `ICollectionViewLiveShaping` sorting/filtering/grouping stay in WPF's managed collection-view, binding, dispatcher, and notification managers. The ProGPU boundary should only see the resulting realized item visuals and render them; it should not duplicate live item shaping or selector/list-manager policy in native or bridge code.

## Current WPF Rendering Boundary

WPF managed rendering persists content in `RenderData`, `Drawing`, `DrawingVisual`, and `Visual` objects. Those objects are marshalled into `DUCE.Channel` command streams and consumed by MIL/native rendering. The Windows-only seams include:

- `DUCE.Channel`, `MILCMD`, and `MilCoreApi` P/Invoke calls.
- `HwndSource`/`HwndTarget` and Win32 message handling.
- D3D, WIC, DWrite, tablet, input, clipboard, drag/drop, and monitor/DPI APIs.

## ProGPU Replacement Boundary

ProGPU replaces MIL/D3D composition with:

- `ProGPU.Backend.WgpuContext` for WebGPU device, queue, surface, and swapchain management.
- `ProGPU.Scene.Compositor` for retained visual rendering.
- `ProGPU.Scene.DrawingContext` and `RenderCommand` for recorded drawing operations.
- Silk.NET windowing for cross-platform surface ownership and event pumping.

## First Port Lane

`src/ProGPU.Wpf` is the initial bridge:

- `ProGpuWpfCompositionTarget` owns a ProGPU context/compositor pair and renders a root ProGPU drawing visual.
- `ProGpuWpfDrawingFrame` prepares the retained ProGPU root visual once per frame, exposes drawing-context factories that can create multiple WPF-shaped drawing-context wrappers over the same command buffer, and tracks owner/count diagnostics for provider-created contexts.
- `WpfRenderDataSinkProviderBridge` is the transition adapter that can install an active frame's drawing-context factory into WPF's internal render-data sink provider once the provider exists in the loaded `PresentationCore` identity.
- `WpfPortablePresentationSourceBridge` is the transition adapter for the real WPF portable source. It can create or bind `System.Windows.PortablePresentationSource` by reflection, mirror its real WPF root visual into `ProGpuWpfWindowHost.WpfRootVisual`, map source render requests into the ProGPU host scheduler, and forward DPI scale changes while `ProGPU.Wpf` still references the shim `PresentationCore` identity.
- `WpfPortableWindowActivation` is the transition adapter above that source bridge. It binds WPF-shaped top-level windows to host-owned portable presentation sources, keeps the WPF window object as the source root visual, derives Silk.NET host options from reflected WPF-shaped title, size, visibility, and window-state properties, forwards live WPF title and client-size changes to the host through the same activation boundary, maps WPF `Closing` cancellation back to Silk.NET `IWindow.IsClosing`, forwards Silk.NET focus-derived activation/deactivation back through WPF `Window.HandleActivate(bool)` via the portable activation service, maps normalized input into WPF-owned portable input args for real `PresentationFramework` windows while preserving explicit transition handlers for WPF-shaped test hosts, forwards external file-drop payloads to explicit transition handlers on the WPF-shaped top-level window when present, and can register a reflection activation factory with real `PresentationFramework` so non-Windows `Window.Show`, `Hide`, `WindowState`, and `Application.Run` reach a ProGPU/Silk.NET host through WPF lifetime code.
- `ProGpuWpfWindowHost` owns a Silk.NET window and forwards each frame to WPF-shaped drawing callbacks. The host can now own an attached portable presentation source through `TryCreatePortablePresentationSource(...)` or `TryBindPortablePresentationSource(...)`, disposing replacement bridges, mirroring root changes, and syncing framebuffer-derived DPI scale each frame.
- `IWpfCompositionCommandSink` is the replacement seam for redirecting WPF managed drawing operations away from `RenderData.WriteDataRecord` and into a backend implementation.
- `ProGpuCompositionCommandSink` is the first sink implementation and forwards WPF-shaped draw calls to the ProGPU shim drawing context.
- `WpfCompositionDrawingContext` is the first source-level adapter for managed draw calls that can bypass MIL byte serialization and call `IWpfCompositionCommandSink` directly while preserving WPF push/pop balancing semantics and reporting unsupported source-level operations.
- `IWpfGeneratedRenderDataDrawingContext` and `WpfRenderDataInstructionRedirectionCatalog` define the current source-level generated-method contract and metadata gate. Tests compare the catalog to WPF's `Resource.xml` render-data instruction definitions so generator-surface drift is caught before the real `renderdata.cs` branch is changed.
- `IRenderDataDrawingContextSink` is now present in the real WPF `PresentationCore` source tree. `RenderDataDrawingContext` can be constructed with that sink, and both the render-data generator and checked-in generated `RenderDataDrawingContext.cs` now redirect to the sink before MIL byte-record serialization while keeping the existing Windows/MIL path as the default. `DrawingContextRenderDataSink` maps the sink surface back onto WPF's managed `DrawingContext`, and `RenderDataDrawingContextSinkProvider.PushDrawingContextFactory(...)` plus `VisualDrawingContext.Create` route `DrawingVisual.RenderOpen()` and `UIElement.RenderOpen()` through a scoped drawing-context factory for future ProGPU composition targets. Provider registrations use a nested scope stack so nested frames or out-of-order disposal restore the nearest still-active drawing route rather than blindly replacing the current route.
- `WpfMilRenderDataDecoder` can decode the primitive generated WPF `RenderData` byte stream format and invoke `IWpfCompositionCommandSink`.
- `WpfReflectionResourceResolver` adapts common real-WPF-shaped dependent resources to ProGPU shim resources while the real WPF assemblies and shim assemblies still have different type identities.
- `IWpfImageSourceAdapter` is an opt-in GPU resource creation boundary for image replay. `WpfBitmapSourceImageAdapter` can copy WPF-shaped bitmap pixels through `CopyPixels(Array, int, int)`, reflect palette colors, delegate WPF/WIC-shaped pixel stride, byte-length, palette, row-conversion, compact-row packing, and BGRA texture upload validation to ProGPU's reusable `PixelDataBuffer`/`Pbgra32PixelBuffer`/`PixelDataConverter`/`GpuTexture` upload contract, and upload the resulting Pbgra32 bytes into a ProGPU-backed shim `WriteableBitmap`.
- `IWpfDrawingResourceResolver` and `WpfReflectionDrawingReplay` handle `MilDrawDrawing` for common WPF-shaped drawing resources without requiring a compile-time WPF dependency, including bounded geometry-fill replay paths for `ImageBrush`, `DrawingBrush`, and `VisualBrush` instances. The source-level object sink reuses the same tile-brush replay entry point for real `DrawingContext.DrawRectangle(...)` and `DrawGeometry(...)` calls instead of adding separate managed fallbacks.
- `WpfRenderDataReflectionBridge` snapshots WPF `RenderData` private buffers and dependent-resource lists for transition replay through `WpfMilRenderDataDecoder`.
- `WpfVisualContentReflectionBridge` extracts `DrawingVisual._content` and `UIElement._drawingContent`, then replays existing WPF `RenderData` content without taking a dependency on WPF assemblies at compile time.
- `WpfVisualTreeReflectionRenderer` recurses through `ContainerVisual.Children`, applies compatible transform/offset/clip/opacity state using the same media adaptation boundary, and records unsupported state while replaying content.
- `IWpfViewport3DCommandSink` and `WpfViewport3DReflectionBridge` provide the first WPF 3D transition path. The bridge reflects WPF-shaped `Viewport3DVisual`, projection cameras, `ModelVisual3D`, `Model3DGroup`, `GeometryModel3D`, `MeshGeometry3D`, and common material/light data into ProGPU's `Mesh3D` compositor extension payload.
- `WpfViewport3DTextureCache` is owned by `ProGpuWpfCompositionTarget` and reuses offscreen color/MSAA/depth textures for reflected Viewport3D content, disposing unused entries after each replay frame.
- `WpfVisualInvalidationTracker` observes common WPF-shaped change notifications and reflected numeric source-version snapshots by reflection, follows visual/content/tile/effect/guideline/shader resource references that the transition replay path can consume, including `DrawingVisual._content` and `UIElement._drawingContent` private content fields used by WPF-managed render ownership, then marks mapped retained ProGPU branches dirty when source visuals/resources change, falling back to the retained root when the current dirty set contains any source that the branch map cannot target exactly.
- `WpfRetainedVisualBranchMap` records the transition mapping from reflected WPF source visuals and replay dependencies to retained ProGPU branch visuals during subtree replay. It distinguishes source owners from dependencies, is cleared with the retained WPF layer, preserved when clean replay is skipped, can invalidate mapped branch visuals for the current dirty source set, can return conservative exact replay targets for dirty sources, unregisters replayed branch subtrees before replacing their mappings, and exposes source/branch plus dirty, mapped, unmapped, invalidated branch, shared-with-clean-owner, replay-target-conflict, and fallback diagnostics through `ProGpuWpfCompositionTarget`.
- `IWpfRenderScheduler`, `CoalescingWpfRenderScheduler`, and `DispatcherWpfRenderScheduler` provide the first render-request boundary between WPF-style invalidation and the Silk.NET host loop. The dispatcher scheduler coalesces pending render requests, uses a one-shot `IWpfTimer` interval for frame pacing, and posts `RenderRequested` at WPF-shaped `Render` dispatcher priority. `ProGpuWpfWindowHost` subscribes to that scheduler event and, when a window exists on the dispatcher owner thread, issues a guarded non-reentrant Silk.NET `DoRender()` wakeup so native ProGPU rendering is not limited to unmanaged polling from application code. When dispatcher or render work arrives from a worker/timer thread or during an active render, the event-driven host wakes the native loop with Silk.NET `IWindow.ContinueEvents()` and leaves actual dispatcher draining/rendering on the window owner thread. The host also drains queued dispatcher work from Silk.NET `Update` callbacks so wake-only dispatcher posts do not have to wait for a render callback. `ProGpuWpfFrameState` adds a host-level snapshot of pixel size, native scene/retained/flat change-version counters, and retained-branch targetability diagnostics so unchanged frame callbacks can be skipped conservatively while branch-mapping quality remains observable.
- `ProGpuWpfCompositionTarget.WpfImageSourceAdapter` and `ProGpuWpfWindowHost.WpfImageSourceAdapter` surface image upload for transition visual replay. The window host defaults this to `WpfBitmapSourceImageAdapter`; callers can replace it or set it to null.
- `IWpfPlatformServices` defines the first local OS abstraction boundary for non-rendering Win32 services. The default host uses `CrossPlatformWpfPlatformServices`, with `ProcessWpfLauncher` replacing simple Win32 `ShellExecute`-style URI/file launch behavior through `ProcessStartInfo.UseShellExecute`, `ProcessWpfClipboard` replacing text clipboard access through platform commands, `ProcessWpfFileDialogService` replacing file open/save/folder picker calls through platform commands, `SilkNetWpfInputService` replacing low-level Win32 keyboard/mouse intake through Silk.NET input, `SilkNetWpfCursorService` replacing Win32 cursor selection through Silk.NET standard cursors, `QueuedWpfDispatcherService` replacing Win32 message-loop posting with owner-thread prioritized callback processing, `DispatcherWpfRenderScheduler` replacing the first MediaContext render scheduling primitive through dispatcher/timer services, `SilkNetWpfDragDropService` replacing the first external file-drop payload intake through Silk.NET file-drop events, `SilkNetWpfWindowEventService` replacing low-level activation and external file-drop message intake through Silk.NET window events, `SilkNetWpfMonitorService` replacing monitor enumeration and DPI scale derivation through Silk.NET/reflected backend metadata, and `ThreadPoolWpfTimerService` replacing Win32 timer dependencies for portable one-shot/repeating timers. Real WPF `MediaContext` now keeps its timing math but routes the performance-counter source through a platform branch, using Windows QPC on Windows and `Stopwatch` count/frequency values on non-Windows. Real WPF `MediaSystem` keeps lifetime bookkeeping but skips MILCore partition and DUCE channel creation on non-Windows, leaving `MediaContext` disconnected until ProGPU/Silk.NET supplies the transport. Real WPF `InputManager` now constructs `PortableKeyboardDevice` and `PortableMouseDevice` on non-Windows instead of `Win32KeyboardDevice`/`Win32MouseDevice`, skips the Windows STA gate outside Windows, and `MouseDevice` uses portable double-click metric defaults outside Windows. Real WPF `PortableCompositionTarget` now provides a non-DUCE root/device-transform owner, real WPF `PortablePresentationSource` owns that target, source registration, root/source-change notifications, content-rendered callbacks, and render requests, and real WPF `PresentationFramework` now has `PortableWindowActivationService` so non-Windows `Window.Show` can activate a registered ProGPU/Silk.NET host before HWND creation. `Window.Hide`, `WindowState`, title/client-size changes, native close cancellation, focus-derived `Activated`/`Deactivated` changes, normalized keyboard/text/mouse/wheel input, and external file-drop payloads forward through the same activation boundary; input is converted to raw WPF reports and enters `InputManager.ProcessInput(...)` for routed promotion, while `Application.Run` skips the hidden parking HWND on non-Windows, can synchronously show the startup window through that activation path, and can run the registered Silk.NET host loop before falling back to `Dispatcher.Run`; Windows `HwndTarget`/`HwndSource` stay on the original HWND path.
- The project references `external/ProGPU/src/PresentationCore`, reusing the existing shim for `System.Windows.Media.DrawingContext`, brushes, pens, geometries, text, and bitmaps.

`ProGpuWpfCompositionTarget.ReplayVisualSubtree` and `ProGpuWpfWindowHost.WpfRootVisual` are the first integration points from WPF-shaped retained visuals into the ProGPU scene. The source-level drawing-context adapter is a prototype for the next generator migration. It should become the branch taken by generated `RenderDataDrawingContext` methods once real WPF `PresentationCore` is compiled in the ProGPU lane. When the active sink supports retained branch mapping, both the typed source-level context and object-shaped real-WPF sink context register applied drawing and pushed-state resources through the same tracked dependency graph as visual replay, preserving original reflected resource identities on the object-sink path.

Direct ProGPU installation of the real WPF sink remains an assembly-boundary decision. `PresentationCore` is strong-named and exposes internals to strong-named friend assemblies; the ProGPU submodule assemblies are now also strong-name signed with public key token `c29c9752855ee183`, but the current `ProGPU.Wpf` bridge still uses the ProGPU shim `PresentationCore` type identity. Until those identities are unified or an explicit signed friend assembly is introduced, sink registration stays as an internal WPF hook that can be activated by the eventual in-assembly or friend-assembly ProGPU target. The current preferred activation path is a ProGPU-backed WPF `DrawingContext`, installed through `PushDrawingContextFactory(...)`, because that keeps generated rendering tied to the managed WPF drawing abstraction rather than a ProGPU-specific interface. `WpfRenderDataSinkProviderBridge` makes this activation explicit and testable: it probes for the internal provider by name, creates the provider's typed factory delegate only when the loaded types are assignable, and fails closed against the current shim where the provider is absent. `WpfPortablePresentationSourceBridge` follows the same assembly-boundary rule for windowing: it probes the loaded real `PresentationCore` assembly for `PortablePresentationSource`, creates or binds it only when the expected source shape exists, and fails closed when running against the shim. `WpfPortableWindowActivation` sits above that bridge with the same reflection boundary and intentionally keeps the WPF-shaped top-level window object as the root visual, matching WPF's model where `Window` is the top-level visual/root rather than a separate content proxy. `PortableWindowActivationService` is the in-assembly `PresentationFramework` hook that lets that reflection bridge register a non-Windows activation factory without making WPF reference ProGPU directly. Portable show now drains WPF `Loaded` and `Render` dispatcher priorities through that service after the Silk.NET host is visible, using the real WPF loaded-event queue instead of a ProGPU-side event shim; render wakeups still drain WPF `Render` priority through the same reflected service lookup.

Real `Application.Run()` remains WPF-owned. The portable path now lets WPF run its own `StartupUri`, `DoStartup`, root `Window.Show`, `MainWindow`, `Shutdown`, and `Exit` logic while replacing only the native loop boundary. On non-Windows, `Dispatcher.PushFrameImpl` drains managed dispatcher work without `GetMessageW`, continues past marker operations when older same-priority startup work remains queued, and `IsInputPending()` reports no Win32 input instead of calling `MsgWaitForMultipleObjectsEx`. This makes dispatcher startup/shutdown flushing a deterministic bridge to the ProGPU/Silk.NET run loop, not a managed rewrite of WPF app lifetime.

Low-level input flows from Silk.NET through `IWpfInputService` and `ProGpuWpfWindowHost.InputReceived`. Real `PresentationFramework` windows instead receive WPF-owned `PortableInputEventArgs` through `Window.HandlePortableInput(...)`; `PortableWindowActivationService.ProcessInput(...)` resolves the active `PresentationSource`, updates `PortableKeyboardDevice`/`PortableMouseDevice` state, builds `RawKeyboardInputReport`, `RawTextInputReport`, or `RawMouseInputReport` instances, normalizes wheel deltas to WPF `MouseWheelDeltaForOneLine` units, and runs them through `InputManager.ProcessInput(...)` so WPF's normal raw-report promotion raises routed key, text, mouse, button, capture, and wheel events. External file drops flow from Silk.NET through `IWpfDragDropService` and `ProGpuWpfWindowHost.DragDropReceived` into explicit portable transition handlers (`OnPortableDrop`, `OnPortableFileDrop`, or `DropFiles`) on the active WPF-shaped window. Remaining input work is deeper focus/advanced capture parity, IME/stylus, synchronized input edge cases, full routed drag/drop (`DragEventArgs`, `DataObject`, drag-enter/over/leave, and effect negotiation), and event-loop wake integration around dispatcher and MediaContext.

Shallow retained dependency ownership is used only for owner-level graph edges such as visual `Children` collections and supported visual `RenderData` content objects. The tracker walks both WPF private content holders (`DrawingVisual._content` and `UIElement._drawingContent`) so reused WPF render-content objects and their dependent resources can dirty the retained owner branch without a ProGPU-side redraw model. Recursive dependency ownership remains reserved for replay resources and visual-state resources that the tracker graph can walk, which avoids making child source visuals dependencies of their parent branch while still letting content-object invalidations target the owner branch.

As of the `96137ca` ProGPU submodule update, chart-series opacity composition, cached layer physical-size refresh, cached layer fractional-size/DPI ceiling, cached layer WebGPU-context validity, cached layer disposal for detached/disabled visuals, and missing-glyph ID 0 outline preservation are treated as native ProGPU responsibilities. The WPF bridge should forward WPF-owned brush opacity, visual opacity, DPI scale, visual size, `CacheMode` intent, and glyph/code-point intent to the ProGPU boundary; it should not add managed-side chart alpha compensation, force dirtying for every DPI-only cache resize, compensate for fractional cached-layer sizing, manage `Visual.LayerTexture` lifetime, or classify glyph IDs as whitespace outside the original WPF text/code-point path.

`ProGpuCompositionCommandSink` records primitive line, rectangle, rounded-rectangle, ellipse, geometry, bitmap image, glyph-run, formatted-text, opacity, clip, opacity-mask, and Viewport3D operations as native ProGPU commands carrying the active WPF transform where applicable. It bypasses the shim `Geometry.Draw` and `DrawingContext.PushClip` fallbacks when WPF geometry can be converted to a ProGPU vector path. Geometry draws record native `DrawPath` commands, preserving path figures, WPF arc metadata, and `PathSegment.IsSmoothJoin` for the compositor. Transformed arcs are kept as native ProGPU `ArcSegment` values through `ProGPU.Vector.ArcSegmentGeometry.TryTransformArcSegment`, including translation, positive scale/rotation fast paths, arbitrary affine shear, and orientation-reversing transforms that flip sweep direction; only truly degenerate arcs fall back to endpoint lines. The ProGPU WPF/WinUI path API shims follow the same rule for parsed SVG/WPF arcs and geometry transforms, so API-level path arcs reach the native vector arc shader instead of being replaced by endpoint line placeholders. The ProGPU `PresentationCore` path shim now preserves original WPF path coordinates and stores `Geometry.Transform` on the native `DrawPath` command; the compositor and path atlas therefore own transformed-arc evaluation for both filled and stroked paths instead of relying on managed shim-side point baking. The same shim-level path conversion is used by `DrawingContext.PushClip(Geometry)`: path-compatible WPF clips record native `PushGeometryClip` commands with `Geometry.Transform` composed with the active drawing transform, so ProGPU's mask path handles non-rectangular clips and transformed arc clips instead of an axis-aligned bounds approximation. Primitive line, rectangle, rounded-rectangle, and ellipse commands apply active dynamic `GuidelineSet`, `PushGuidelineY1`, and `PushGuidelineY2` snapping before command recording when the current transform is axis-aligned; `PushGuidelineY2` preserves the driven-edge offset. WPF-shaped `LineJoin`, `MiterLimit`, and `PenLineCap` values are copied through the shim `Pen` into native ProGPU vector pens on recorded commands, with miter limits clamped to WPF's effective minimum of `1.0`. ProGPU vector path stroking now emits native filled triangle geometry for miter, bevel, and round joins between adjacent line, quadratic Bezier, cubic Bezier, and arc segments using endpoint tangents, falls back from miter to bevel when the miter limit is exceeded, suppresses hard join filler geometry when the incoming path segment carries `IsSmoothJoin`, emits native square, round, or triangle cap geometry for open line, quadratic Bezier, cubic Bezier, and arc paths using endpoint tangents, and emits valid arc strokes as fixed-quad `ArcSdf` primitives by creating reusable `ProGPU.Vector.ArcShaderParameters` for transformed ellipse center/axis vectors and passing that native arc ABI to vector WGSL for fragment-level nearest-ellipse and WPF/SVG sweep evaluation. The older segmented `ArcStrip` compositor/WGSL path has been removed, so valid arcs no longer have a strip-tessellation fallback. Positive and dot-style dash-array pens now delegate WPF dash-array normalization, odd-array duplication, dash-offset state, and dot-dash promotion to `ProGPU.Vector.DashPattern`; straight `DrawLine` calls and rectangle outlines replay as native line segment commands in local coordinates while preserving active transforms and continuous rectangle dash phase. Dashed path-compatible geometries keep WPF arc, quadratic Bezier, and cubic Bezier spans native by requesting visible dash intervals from `ProGPU.Vector.ArcSegmentGeometry.TryCreateDashedArcSegments(...)` and `ProGPU.Vector.BezierSegmentGeometry.TryCreateDashed*BezierSegments(...)`, then recording those spans as one-segment `DrawPath` commands; dash state advancement stays in ProGPU vector helpers, and rendering stays on the ProGPU arc/Bezier shaders instead of bridge-local line fallback geometry. Skia `SKPaint` dash path effects now map into the same native vector pen dash metadata, so Skia/WPF-compatible API users share backend-owned dash lowering rather than duplicating managed span emitters. Positive dash-array rounded-rectangle and ellipse outlines build ProGPU-owned primitive paths through `ProGPU.Vector.PrimitivePathGeometry`, so rounded corners and ellipse curves emit native arc dash commands instead of bridge-local polyline approximations; filled dashed primitives or geometries emit the fill before the segmented outline. Filled dashed combined geometries keep their native combined fill and emit operand-boundary dashed outline segments with unsupported-fidelity diagnostics until exact boolean-result dashed outlines are implemented. Transition-emitted line segments support WPF `Square` caps by extending endpoints by half the pen thickness, `Round` caps by emitting filled circular cap geometry, and `Triangle` caps by emitting filled triangle geometry with the apex one pen radius outward. Shim bitmap image draws and adaptable real WPF `BitmapSource` image draws record native `DrawTexture` commands through the image-source adapter. Shim-compatible glyph runs record native `DrawGlyphRun` commands with the glyph-run transform composed with the active WPF transform. Shim-compatible formatted text records native `DrawText` commands with the active WPF transform. Opacity scopes record native `PushOpacity`/`PopOpacity` commands. Clip scopes record native `PushGeometryClip`/`PopGeometryClip` commands, preserving non-rectangular clip intent. Native opacity-mask scopes carry the active WPF transform in the recorded ProGPU command. Null generated clip, transform, and opacity-mask resources are represented as no-op sink scopes so later pops preserve WPF stack semantics without emitting native rendering state. Reflected Viewport3D visuals record a `DrawExtension` Mesh3D command to render into the cached offscreen target, then a transformed `DrawTexture` command to composite that target into the 2D visual tree. Geometries that cannot produce a path and image sources whose pixels/codecs/color profile cannot yet be adapted still fall back to shim behavior until their managed representation is ported.

The ProGPU shim formatted-text path now keeps WPF-compatible `System.Windows.FontWeight`, `FontStyle`, and `FontStretch` value semantics and copies typeface-derived bold/slanted intent into native `DrawText` command metadata. That keeps reused WPF-shaped managed text calls on the same command-recording path as GDI and glyph-run style simulation instead of adding bridge-side text style compensation.

As of the `ba59fdf` ProGPU submodule update, the production dashed-combined-geometry path no longer has to use operand-boundary outlines when a WebGPU context is available. `ProGpuCompositionCommandSink` resolves the native combined `PathGeometry` through `PathOpGeometrySolver` and dashes the boolean-result boundary; only context-free transition/test fallback keeps the older operand-boundary dash emission and unsupported-fidelity diagnostic. The same bridge conversion now forwards WPF `PathGeometry.FillRule` and every path segment's `IsStroked` flag into the ProGPU vector path ABI before recording native commands.

Rectangular clip scopes intentionally stay on ProGPU's native scissor path. The compositor now transforms all four local clip corners before deriving the conservative screen-space scissor bounds, so rotated or sheared WPF visual clips, scrollable-area clips, and unsupported-geometry rectangular fallbacks do not need managed WPF-side compensating bounds code.

Combined geometry is now part of the ProGPU-owned vector path model for WPF shim users as well as the transition bridge. `ProGPU.Vector.PathGeometry.CreateTransformed(...)` preserves line, quadratic, cubic, and arc segment metadata while baking child transforms into native path-op operands, and shim-level `CombinedGeometry` maps WPF `Union`, `Intersect`, `Xor`, and `Exclude` to ProGPU path-op ids instead of forcing bounds fallback.

Primitive WPF shim geometries now use the same native path representation. `LineGeometry`, `RectangleGeometry`, `EllipseGeometry`, and `GeometryGroup` expose `TryGetPathGeometry(...)`; rectangles and ellipses reuse `ProGPU.Vector.PrimitivePathGeometry`, so ellipse/group clips keep native arc segments and path masks. Shared `ProGPU.Vector.PathGeometry.TryGetBounds(...)` computes ordinary and combined path bounds, including transformed arc bounds after `CreateTransformed(...)`, so shim geometry bounds no longer need duplicate managed arc/bounds code. WPF `PathGeometry.Draw(...)` also splits fill and stroke only when a figure has `IsFilled=false`, excluding those figures from fill atlas commands while leaving the full path available to native stroke commands.

WPF path fill and stroke metadata is now part of the ProGPU vector ABI. `ProGPU.Vector.PathGeometry.FillRule` is carried into `GpuPathRecord.FillRule`, where the path rasterizer and path-op shaders choose `EvenOdd` or `Nonzero` winding behavior natively. The WPF transition bridge, WPF `PresentationCore` shim, WPF `GeometryGroup`, and WinUI path shim forward their API fill rules into that field. `PathSegment.IsStroked` is preserved from WPF `StreamGeometryContext` and through ProGPU affine transforms, Bezier/arc subdivision, and path-op figure copies; fill compilation still sees every segment, while stroke tessellation skips non-stroked segments and treats them as contour breaks for caps and joins. This keeps WPF-compatible path semantics in ProGPU rather than adding managed contour-rewrite or stroke-filter workarounds in the WPF bridge.

## Managed WPF Reuse Strategy

The migration should move WPF managed code in layers:

1. Keep dependency properties, Freezable, animation clocks, visual tree, layout, and drawing object model managed.
2. Redirect generated `RenderDataDrawingContext` methods from `RenderData.WriteDataRecord(MILCMD, ...)` to an in-assembly sink, route visual render-open through a scoped provider, then bridge that sink through `WpfRenderDataSinkProviderBridge`, an active `ProGpuWpfDrawingFrame`, and ProGPU-backed WPF `DrawingContext` to `IWpfCompositionCommandSink` in the ProGPU lane.
3. Use `WpfCompositionDrawingContext` as the source-level adapter for new ProGPU render targets, and keep `WpfRenderDataReflectionBridge` plus `WpfMilRenderDataDecoder` as a compatibility bridge for existing `RenderData` buffers during the transition.
4. Replace DUCE resource creation/update/release with ProGPU resource handles and command references.
5. Replace `HwndTarget`/`HwndSource` on non-Windows with `PortablePresentationSource` plus a Silk.NET-backed ProGPU host while keeping WPF's `PresentationSource` and `CompositionTarget` API shape.
6. Replace native helpers with platform services or pure managed implementations.
7. Fold the ProGPU shim back into the real WPF assemblies once enough native-only seams are abstracted.

The reflection bridge is a transition mechanism, not the final architecture. Once managed WPF code compiles in the port lane, the preferred path is to expose `RenderData` snapshots or redirect generated render-data writers in assembly rather than relying on private-field reflection.

The reuse rule applies to XAML serialization as well as rendering. `XamlReader`, `XamlWriter`, `ResourceDictionary`, `ResourceKey`, theme-style keys, namescope, resource-expression, binding, template, style-trigger, rich document object graphs, and XAML compiler behavior should remain in the ported WPF managed assemblies. The ProGPU boundary should receive rendered visual/resource intent and native platform events. If the serializer reaches internal WPF concepts such as `SystemResourceKey`, `SystemThemeKey`, default empty runtime-name properties, or rich text default property state, the durable fix is to make the WPF serializer express or suppress those concepts through WPF's existing XAML forms, not to add a ProGPU-side serializer or managed object-graph workaround.

Visual subtree replay currently covers `DrawingVisual` and `UIElement` content backed by `RenderData`, `MilDrawDrawing` for common drawing resources, child traversal through `Children` and real-WPF-shaped protected `VisualChildrenCount`/`GetVisualChild(int)`, compatible transform/offset/native-primitive-draw/native-geometry-draw/native-geometry-clip/scrollable-area-clip/opacity/opacity-mask/guideline state, supported `BitmapScalingMode=NearestNeighbor`/`LowQuality`/`Linear`/`HighQuality`/`Fant` image-sampling state, supported `EdgeMode=Aliased` vector edge state, supported `TextRenderingMode=Aliased`/`Grayscale`/`ClearType` text antialiasing state, reflected Viewport3D mesh payload compilation, and reflection adaptation for solid brushes, linear and radial gradients with large stop tables, bounded mapping/spread/invertible affine brush-coordinate transforms/color-interpolation methods, radial gradients with separate X/Y radii and gradient origins, pens, matrix/translate/scale/rotate/skew/transform-group affine transforms, line geometry, rectangle geometry, ellipse geometry, geometry groups, combined geometry, reflected path geometry, parseable path geometry, simple glyph runs, bounded `ImageBrush`, `DrawingBrush`, and `VisualBrush` geometry fills with relative/absolute viewports, relative/absolute cropped viewboxes, adaptable affine absolute and relative brush transforms, `AlignmentX`/`AlignmentY`, `Stretch=None`/`Fill`/`Uniform`/`UniformToFill`, and bounded `TileMode=Tile`/`FlipX`/`FlipY`/`FlipXY` replay, and opt-in bitmap source upload for common 32-bit, 24-bit, packed grayscale, indexed palette, 16-bit grayscale/BGR, 48/64-bit integer RGB/RGBA, non-profiled scRGB float, and non-profiled CMYK formats. Visual opacity masks use reflected bounds, render size, actual size, or finite bounds inferred from replayable self or child render-data content, including transformed content records. Reflected drawing groups report partial replay when supported children draw but unsupported siblings remain, so bring-up diagnostics do not hide missing content. Reflected geometry groups preserve their fill rule and bake child path transforms into copied figures during pure-path flattening; mixed groups containing combined geometry are folded into ProGPU union combined-path trees so path children and nested boolean content both survive native command emission. Reflected path geometry preserves figures, fill rule, line/polyline, quadratic/polyquadratic bezier, cubic/polycubic bezier, and arc segment metadata. Reflected combined geometry preserves WPF `Union`, `Intersect`, `Xor`, and `Exclude` as ProGPU combined vector paths using operation ids `2`, `1`, `3`, and `0` respectively; `Exclude` maps to ProGPU difference `A - B`. Geometry-owned transformed arcs, transformed arc clips, and transformed arcs inside flattened geometry groups stay native ProGPU arc segments via the ProGPU affine arc transform helper, falling back to lines only for degenerate arcs. Supported visual `BlurEffect`, `DropShadowEffect`, registered WPF `ShaderEffect` replacement descriptors, and context-bound emulatable legacy `BitmapEffect` descriptors can replay through retained ProGPU effect visuals. Unregistered WPF `ShaderEffect`, non-emulatable bitmap effects, non-context bitmap-effect inputs, cache mode, unrecognized bitmap scaling modes, `ClearTypeHint`, and text hinting mode are counted as unsupported visual state during transition replay until their resource mapping is explicit instead of being silently ignored.

The Viewport3D reflection path is intentionally a transition bridge. It does not compile WPF 3D types directly; it reflects WPF-shaped objects and creates ProGPU `Viewport3DCompilationPayload` instances. It supports perspective and orthographic projection-camera matrices, mesh positions, indices, normals or generated normals, model transforms, front/back materials, diffuse/specular/material-group colors, and simple directional/ambient light hints. It does not yet implement WPF 3D hit testing, `Viewport2DVisual3D`, texture brushes as mesh materials, animation clocks, camera controller behavior, exact WPF lighting/material semantics, or retained geometry-version invalidation once the real WPF assemblies are compiled into the port lane.

Transition invalidation now has a reflection tracker for source objects that expose `Changed`, `Invalidated`, `INotifyPropertyChanged`, `INotifyCollectionChanged`, or common numeric version members such as `Version`, `ChangeVersion`, and `_version`. The tracker follows common visual/resource references such as children, content, drawing collections, brushes, pens, geometries, path figures/segments/points, combined-geometry operands, gradient stops, image sources, glyph runs, transforms, relative brush transforms, visual-brush source visuals, clips, opacity masks, effects, bitmap-effect inputs, shader pixel resources/register fields, cache modes, guideline sets, and Viewport3D camera/model/material/mesh collections. It records dirty source identity for attach, event, property-change, collection-change, and reflected version-poll invalidations so later source-object-to-native-branch mapping can produce dirty rectangles instead of falling back to whole-tree replay. `ProGpuWpfCompositionTarget` attaches this tracker during visual replay and invalidates the ProGPU root visual when the source graph changes. `ProGpuWpfWindowHost` polls `DetectWpfSourceChanges()` before frame-state capture, so version-only source mutations are converted into native retained-root invalidation before an unchanged-frame skip is considered.

Render requests are coalesced through `IWpfRenderScheduler`. `ProGpuWpfWindowHost` requests a render when the root visual changes, the Silk.NET surface resizes, the target loads, title/client-size/visibility/window state changes, or the tracked WPF source graph invalidates through notifications or version polling. The default host now owns a `DispatcherWpfRenderScheduler` when platform dispatcher/timer services are available; callers can still replace `WpfRenderScheduler` with a custom scheduler, and unavailable platform services fall back to immediate coalescing. Scheduler wakeups are connected back to the Silk.NET host through a dispatcher-thread, non-reentrant `DoRender()` guard and are detached when schedulers are replaced or the host is disposed. In real WPF `PresentationCore`, `MediaContextNotificationWindow` now avoids hidden HWND/user32/MILCore notification-window setup on non-Windows; Windows keeps the original DWM/channel-message behavior. `MediaContext` timing now also avoids non-Windows `kernel32` by using `Stopwatch` as the count source while keeping the existing WPF count/frequency conversion helpers. `MediaSystem` now keeps lifetime bookkeeping but skips MILCore partition and DUCE channel creation on non-Windows, leaving `MediaContext` disconnected until a ProGPU/Silk.NET transport exists. Disconnected portable render scheduling also skips MIL interlocked-presentation entry when no DUCE channel exists, while still posting the portable render wakeup. Real WPF `HwndTarget` remains the Windows HWND-backed target, but its Win32 message registration is guarded so the type can load off Windows and construction fails before session/HWND/MIL initialization. Real WPF `PortableCompositionTarget` now owns roots and device transforms without DUCE channel resources, and `PortablePresentationSource` provides the matching non-HWND `PresentationSource` root/source/render-request boundary. The host-owned `WpfPortablePresentationSourceBridge` attachment APIs and `WpfPortableWindowActivation` bind that real source to the current Silk.NET `ProGpuWpfWindowHost` by reflection, keep the WPF window object as the root, derive initial host title/size/window state, keep live WPF title/client-size, DPI/root/render-request state synchronized, expose native close callbacks back to WPF `Window.Close()` with WPF `Closing` cancellation mirrored to Silk.NET `IWindow.IsClosing`, forward WPF hide/minimize/maximize state to Silk.NET, forward Silk.NET focus changes through WPF `Window.HandleActivate(bool)` for `IsActive`/`Activated`/`Deactivated`, route normalized keyboard/text/mouse/wheel payloads into WPF `InputManager`, forward external file-drop payloads to explicit portable transition handlers, and let real non-Windows `Application.Run` run the Silk.NET host loop. Basic caret cleanup now guards Win32 caret-blink lookup on non-Windows and takes WPF's existing no-blink path. This is still not full WPF `MediaContext` or windowing: keyboard focus/capture edge cases, dirty-region calculation, portable channel notifications, deeper OS event-loop wake integration, animation ticks, IME/stylus, routed drag/drop, shutdown edge cases, and in-assembly `Visual` change flags still need to be ported.

Glyph-run adaptation preserves WPF glyph indices, baseline origin, font rendering size, advance widths, optional glyph offsets, and reflected `GlyphTypeface.StyleSimulations` bold/italic flags, then resolves the closest available ProGPU `TtfFont` from a reflected local `GlyphTypeface.FontUri`/font file path when available, by WPF glyph typeface family name when not, or by platform fallback as a last resort. Successfully loaded font files are cached by path so repeated glyph-run replay does not reload the same font data. Once adapted, the composition sink records the run as a native ProGPU `DrawGlyphRun` command carrying the active transform and style-simulation flags.

This glyph path is an intermediate replay bridge. It does not replace WPF text formatting, LineServices, DWrite shaping, bidirectional text handling, font fallback chains, caret stops, or full glyph typeface simulation and fallback identity beyond the current bold/italic simulation flags. The in-tree portable text boundary now source-shares ProGPU's basic one-scalar-to-one-glyph analyzer fallback with cluster maps and metric-derived advances, but it deliberately does not implement OpenType feature shaping, ligatures, contextual substitution, mark positioning, or complex script handling. The real-theme replay now keeps the implicit-style Fluent `CheckBox` visible by classifying private-use icon-font scalars as simple fast text on non-Windows and allowing missing private-use glyphs to use WPF's null-glyph unshaped `GlyphRun` placeholder when Segoe Fluent/MDL2 is unavailable. That keeps the real WPF theme/control tree measurable without entering native `TextFormatterContext.LoCreateContext`, but exact icon fallback is still unresolved. The remaining text concerns still need a deliberate stack decision: route WPF formatted text through ProGPU's text APIs or introduce a cross-platform shaping/line-formatting layer before emitting ProGPU glyph commands.

The root `PresentationCore` and `PresentationFramework` build graphs now succeed on macOS after the SDK/build-tool bring-up changes, the non-Windows `MS.Internal.Text.TextInterface` boundary documented in `progpu-wpf-text-stack.md`, and Windows-only guards around every managed-graph `DirectWriteForwarder.vcxproj` reference in `PresentationCore`, `ReachFramework`, and `PresentationFramework`. The text boundary preserves the managed shape WPF expects from DirectWriteForwarder and now includes source-shared ProGPU helpers for file-backed SFNT metadata, cmap glyph mapping, metrics, embedding rights, GSUB/GPOS/GDEF table access, simple glyph mapping/placement, and glyph-ID-preserving TrueType subset writing. ProGPU.Text also now owns a compact glyph-remapping TrueType subsetter with source-to-subset glyph maps and composite component rewrites; WPF should stay on the preserving subset API until `GlyphTypeface.ComputeSubset` or its embedding caller can propagate that map. Direct `ProGPU.Text` project references from root WPF assemblies are still deferred while the TFM/project graph is split, so focused ProGPU text helpers are source-shared as internal WPF implementation details. This confirms the next in-assembly port boundary: replace the source-shared simple analyzer fallback, remaining CFF subsetting gaps, and LineServices seams with real cross-platform implementations before claiming formatted text fidelity, then move from buildable managed assemblies toward a Silk.NET-backed `CompositionTarget`/windowing path.

Image replay is deliberately explicit because it allocates GPU textures and must respect the active ProGPU context. The low-level reflection resolver uses exact ProGPU shim identity unless an `IWpfImageSourceAdapter` is supplied. The composition target exposes that adapter for replay calls, and the Silk.NET window host enables `WpfBitmapSourceImageAdapter` by default so WPF-shaped retained visuals can draw common bitmap content during bring-up. Once an image has shim `BitmapSource` identity, the sink records it as a transformed native `DrawTexture` command. The first adapter now keeps WPF reflection, palette extraction, `CopyPixels(...)`, and `WriteableBitmap` construction in the bridge, while ProGPU.Backend owns reusable upload normalization through `PixelDataBuffer`, `Pbgra32PixelBuffer`, `PixelDataConverter`, and `GpuTexture.WritePbgra32SubRect(...)`: source stride and byte-length calculation, indexed-palette requirement checks, Pbgra32 conversion for premultiplied/straight BGRA/BGR formats, compact-row packing for padded sources, BGRA texture-format validation, and sub-rectangle bounds checks before WebGPU upload. Full WIC replacement still needs platform codecs, metadata/color-profile policy, caching, invalidation, download state, texture-backed bitmap sources, and lifetime management.

Shader effects should be ProGPU-native rather than managed pixel loops. ProGPU.Scene now includes a `WpfShaderEffect` compositor extension with a WebGPU/WGSL execution contract for WPF-style `c#` constants packed as 32 `vec4<f32>` registers, bounds/texture-size uniforms, source-register metadata, a fixed 16-slot sampler-register bank, transparent fallback textures for unbound samplers, explicit compositor-compatible pipeline layouts, cached native texture bind groups, and cached render pipelines. `WgpuContext` requests and records sampled-texture, sampler, and bind-group limits, and `WpfShaderEffectExtensionPipeline` keeps active masks bound for all-16-register WPF shader effects only when the actual device can bind the extra mask texture/sampler. Devices that cannot bind the additional mask resource skip that draw with a transient backend diagnostic but leave the reusable `WpfShaderEffectParams` valid, so the same WPF effect can render again when the mask scope is removed. Native WPF shader-effect and image-effect pipelines include source alpha mode and active blend mode in their pipeline keys, and WPF shader-effect shader-module keys also include source alpha mode because the WGSL fragment wrapper is specialized per alpha convention. This keeps premultiplied offscreen visual sources and WPF/Skia/GDI blend scopes in the backend instead of requiring managed-side pixel workarounds. WPF shader-effect WGSL wrappers branch by source alpha mode: premultiplied sources scale RGB and alpha by opacity/mask coverage, while straight-alpha sources keep straight RGB and scale only alpha/coverage before straight-alpha blending applies coverage once. Image-effect color operations now run in straight color space for premultiplied sources and premultiply output again inside the native image-effect shader path, preserving WPF-style color math without a managed prepass. The ProGPU backend also owns WPF-compatible alpha semantics for general texture, vector/text, image-effect, Skia surface, and GDI bitmap paths: straight-alpha `Src`, `Plus`, and fixed-function-incomplete `DstOver` writes reach premultiplied render targets through native blend or premultiplied shader-entry selection, mask render passes use mask-specific WGSL entry points for `R8Unorm` vector/text/texture targets so computed alpha is stored in the sampled red channel, straight image effects apply opacity once by keeping straight RGB and scaling coverage, straight-alpha texture masks scale coverage once while premultiplied texture masks scale RGB and alpha together in the native texture shader path, CPU-backed `SKSurface` uploads unpremultiplied buffers as premultiplied render-target contents and converts readback to the requested `SKAlphaType`, loaded straight-alpha `System.Drawing.Bitmap` contents are premultiplied before being preserved into GPU draw flushes, solid-color `SKPaint` blend-mode color filters are applied before brush/pen conversion while shader/image color-filter combinations fail explicitly until native filter pipelines exist, and swapchain configuration now falls back to advertised present modes instead of forcing unsupported `Immediate` mode. Shader WGSL can use `wpf_sample_source(uv)` for the reflected WPF implicit input, even when that input is not sampler register 0, or `wpf_sample_register(registerIndex, uv)` for explicit sampler-register inputs. The backend resolves the declared WPF source register before sampler register 0 when selecting primary texture metadata, so source alpha mode and texture-size uniforms match `wpf_sample_source(...)`. The ProGPU backend also has a visual-level `ProGPU.Scene.WpfShaderEffect` descriptor that renders the affected `Visual` into an offscreen texture, binds that visual source to the reflected WPF implicit-input sampler register, and replays the shader through the same native WebGPU extension on the main pass. The WPF bridge can reflect WPF-shaped `BlurEffect` and `DropShadowEffect` objects into ProGPU-native `BlurEffect`/`DropShadowEffect` descriptors, can reflect supported context-bound legacy `BitmapEffect` objects through WPF's modern-effect emulation descriptor without running a managed pixel path, and can reflect WPF-shaped `ShaderEffect` objects into `ProGPU.Scene.WpfShaderEffect` when a native WGSL replacement is registered by effect type, pixel-shader URI, or pixel-shader bytecode hash. `WpfShaderEffectRegistry` is intentionally a native replacement registry, not a CPU shader fallback: it provides the ProGPU shader source and stable shader key while reflected WPF float constant registers, implicit input sampler register, image-backed `ImageBrush` sampler registers, compositor-rendered finite `DrawingBrush`/`VisualBrush` sampler registers, nearest/linear sampling mode, and shader padding are copied into the ProGPU descriptor. The Silk.NET host now replays `WpfRootVisual` through a retained ProGPU scene layer. `ProGpuRetainedCompositionCommandSink` creates bounded retained drawing visuals for supported visual-effect scopes, localizes effect content into the inferred bounds, and lets ProGPU's native `Visual.Effect` path perform the offscreen blur/drop-shadow/shader work. Reflected `DrawingGroup` replay also uses this retained effect-scope path for supported group `Effect` descriptors and context-bound emulatable bitmap effects, wrapping child drawing replay without managed pixel processing. The WPF bridge's `WpfShaderEffectSamplerTextureCache` renders finite replayable shader sampler brushes into cached ProGPU textures through the same `DrawingBrush`/`VisualBrush` replay path used for geometry fills, and clears that cache when the retained WPF root is rebuilt. The direct flat replay path still reports visual effects as unsupported because it has no retained visual boundary. The remaining WPF work is non-emulatable bitmap effects, non-context `BitmapEffectInput`, advanced/unbounded brush shader sampler inputs, other non-image sampler texture inputs, and translation/import for legacy Direct3D pixel-shader bytecode, because WebGPU cannot execute that bytecode directly.

Mutable effect invalidation is also native scene state. `ProGPU.Scene.EffectBase` keeps weak owner links to visuals that reference an effect, and effect property changes invalidate those owners so normal parent dirty propagation refreshes cached layers and retained effect textures. The WPF bridge should pass WPF effect intent into ProGPU descriptors and should not add a separate effect-polling or managed replay invalidation layer for this case.

Advanced blend modes that fixed-function WebGPU cannot express correctly for straight source RGB stay native by selecting shader entry-point variants rather than by rewriting WPF commands. `DstOver`, `Screen`, and `Multiply` now use premultiplied fragment entries for vector, text, and straight-alpha texture draws before the backend blend factors run, while already-premultiplied textures keep the normal entry point. This preserves WPF/Skia-style semi-transparent blend behavior and avoids managed bridge-side shader or color premultiplication passes.

Generic ProGPU texture construction is treated as an upload-oriented API and defaults to straight-alpha RGBA semantics for existing `WritePixels(...)` callers. Textures that are rendered into or that store WPF PBgra/render-target contents opt into `GpuTextureAlphaMode.Premultiplied` at allocation, including Skia surfaces, GDI bitmaps, WPF `WriteableBitmap`, host offscreen targets, retained layers, and effect scratch textures. This keeps alpha convention at the backend resource boundary rather than requiring WPF bridge-side pixel rewrites.

GDI and Skia API compatibility should continue to be normalized in the ProGPU shim/backend layer before WPF bridge code compensates. `System.Drawing.Graphics` now scales stroke thickness under world transforms for line, primitive, and path strokes before recording native ProGPU pens. Skia opaque bitmap uploads now normalize alpha bytes to 255 at `SKImage.FromBitmap(...)`, because Skia treats those alpha bytes as ignored while ProGPU textures still carry concrete alpha. CPU-backed `SKSurface` row strides are validated before texture allocation and reused for upload/writeback, so undersized caller buffers fail at the shim API boundary instead of being worked around in WPF interop code. Two-point conical gradients now have a ProGPU-native brush type and WGSL sampler that solves the moving-circle gradient parameter per fragment, so Skia focal/conical gradients can stay on the full GPU path instead of falling back to wrong radial output or managed pixel work. Wrapped backend render targets now carry `GRSurfaceOrigin` into `SKSurface`, and `BottomLeft` targets render through a GPU-side root y-flip during flush so Skia's top-left canvas coordinates land in the correct bottom-left-oriented backend texture without a CPU row-copy workaround. ProGPU compositor render entries now scope the thread-static `WgpuContext.Current` to the active compositor context, and GPU line/scatter buffers track their owning context so render-thread uploads and bind-group cleanup do not depend on the initialization thread. Cached visual layer textures are now valid only for their owning `WgpuContext`, and the compositor releases stale layer textures when their owner visual leaves the active tree, disables layer caching, becomes hidden, points at a different texture, or already holds a disposed texture. Cached texture/mask bind groups, chart line/scatter series bind groups, cached layer textures, and explicitly disposed `GpuBuffer` handles are queued for `WgpuContext` cleanup and released before texture views/textures or context teardown, keeping sampler, buffer, and layer texture lifetime in the backend's ordered render-thread disposal path. `SKSurface.Flush()` also releases canvas-owned `SaveLayer` textures after submitting and clearing the parent draw commands, keeping long-lived Skia-compatible surfaces from retaining one GPU texture per layer per frame.

`System.Drawing.Graphics.DrawImage(...)` interpolation is also a ProGPU compatibility-boundary responsibility. The shim maps `Graphics.InterpolationMode` into the native texture sampler (`NearestNeighbor` to nearest sampling, bicubic modes to cubic sampling, and the remaining GDI+ modes to linear sampling) when recording `DrawTexture`, so WPF/GDI-compatible image draws can keep their managed API shape while ProGPU owns full-speed sampler selection.

Bitmap image sampling is now part of the transition visual-state bridge. Reflected `BitmapScalingMode=NearestNeighbor` pushes a scoped nearest-neighbor texture-sampling mode into `ProGpuCompositionCommandSink`; `LowQuality`, `Linear`, `Unspecified`, `Default`, and `Auto` use linear sampling, matching WPF's native aliasing of `LowQuality` and `Linear` to the same interpolation mode; and `HighQuality`/`Fant` use shader-side cubic texture sampling. Native ProGPU `DrawTexture` commands carry that sampling mode, and the compositor includes it in texture bind-group cache keys so nearest, linear, and cubic texture draws do not alias for the same texture. The same supported modes are replayed for WPF-shaped `DrawingGroup.BitmapScalingMode`; unknown bitmap-scaling values report partial replay when supported children still draw. Reflected visual and drawing-group `EdgeMode=Aliased` pushes a scoped vector edge state into `ProGpuCompositionCommandSink`; native ProGPU vector commands carry `RenderCommand.IsEdgeAliased`, the compositor encodes it into the existing `ShapeType` vertex channel, and the vector shader thresholds primitive, stroke, curve, and path-atlas coverage instead of smoothing it. Reflected visual and drawing-group `TextRenderingMode=Aliased`/`Grayscale`/`ClearType` pushes scoped text antialiasing state into `ProGpuCompositionCommandSink`; native ProGPU text commands carry `RenderCommand.TextRenderingMode`, the compositor encodes the mode into the existing text flags channel while preserving the `IsTextAliased` compatibility property, and the text shader thresholds glyph atlas alpha for aliased text, leaves grayscale text on the current smoothed glyph path, and renders ClearType text with RGB subpixel atlas samples. WPF-shaped `DrawingGroup.ClearTypeHint` and text hinting remain unsupported render-option state until their semantics have explicit native backing.

The first tile-brush transitions are intentionally bounded. WPF-shaped `GeometryDrawing` fills and source-level object-sink rectangle/geometry fills can replay `ImageBrush`, `DrawingBrush`, and `VisualBrush` instances when the brush uses relative or absolute viewport units, relative or absolute viewbox units, `TileMode=None`, bounded `TileMode=Tile`, bounded `FlipX`, bounded `FlipY`, or bounded `FlipXY`, `Stretch=None`, `Stretch=Fill`, `Stretch=Uniform`, or `Stretch=UniformToFill`, `AlignmentX=Left`/`Center`/`Right`, `AlignmentY=Top`/`Center`/`Bottom`, and an absent, identity, or adaptable affine `Transform`/`RelativeTransform`. Relative transforms are converted through the finite filled geometry bounds before replay. Tiled paths require finite fill geometry and cap replay expansion. ImageBrush non-full viewboxes are emitted through `IWpfCompositionCommandSink.DrawImage(..., sourceRectangle)` and ProGPU `DrawTexture.SrcRect` when the adapted image exposes pixel dimensions. DrawingBrush and VisualBrush non-full viewboxes are handled by mapping the selected source bounds into the brush viewport and pushing a transformed source-space clip before nested drawing or visual replay. Non-fill stretch aligns source content inside each tile; oversized `UniformToFill` and source-sized `None` content is clipped to the tile before replay. Flip tiling mirrors alternating tile columns and/or rows by emitting destination-space mirror transforms. All three paths clip to the adapted fill geometry and preserve brush opacity. Non-affine or unreadable transform types and advanced visual-brush cases remain unsupported and are counted as partial unsupported content when a supported stroke, nested drawing subset, or visual subtree subset can still be replayed.

Visual replay still needs richer adapters for remaining tile-brush cases including non-affine or unreadable transform types and advanced visual-brush state, platform codecs, color management and color-profile fidelity, formatted text, complex glyph/typeface identity beyond local font-file URI and bold/italic style-simulation replay, animation resources, remaining non-emulatable drawing effects mapped onto ProGPU-native shader descriptors, visual masks whose finite bounds are not exposed or inferable from replayable content, WPF `ShaderEffect` bytecode translation/import plus advanced/unbounded brush or non-image sampler resource binding, non-context bitmap-effect inputs, multiple-effect-source or inherited effect/cache retained branch replay, non-axis-aligned/exact WPF guideline snapping fidelity, exact curve-join fidelity beyond the current endpoint tangent approximation, exact smooth-join rasterization fidelity, exact cap clipping at complex joins, exact boolean-result combined-geometry dash outlines, cache state, `ClearTypeHint`, text hinting, advanced 3D interop, and in-assembly retained invalidation/render scheduling. Drawing-resource opacity masks can now use reflected `DrawingGroup.Bounds` or infer finite child-content bounds, intersected with adaptable group clips, before recording native ProGPU opacity-mask scopes. Visual opacity-mask inference now also projects inferred child content bounds through child visual offset/transform and simple child clip/scroll-clip bounds before unioning them into native retained `Visual.OpacityMask`/`OpacityMaskBounds` state; adaptable bounded visual masks can keep retained owner branches while descendants remain separate retained child visuals. Remaining mask work is for non-adaptable clips/transforms, unbounded content, advanced visual-brush/effect state, and exact dirty-region/invalidation policy for mask resources.

The combined-geometry dash item above is narrowed by the `ba59fdf`/WPF bridge update: boolean-result outlines are now used when a ProGPU context can run path ops. Remaining work is to move dashed/stroked path emission fully behind backend-owned commands so the WPF bridge no longer emits transition dash spans, and to replace the context-free fallback with an equivalent deterministic path-op service if needed.

## Win32 Abstraction Strategy

Win32 usage should be split into three groups:

- Rendering/windowing: move to Silk.NET and ProGPU.
- OS services: introduce local platform abstractions for clipboard, file dialogs, input, window events, monitor/DPI, cursor, drag/drop, dispatcher posting, timers, activation, and MediaContext/channel wakeups. Simple URI/file launching is routed through the cross-platform `ProcessWpfLauncher`; text clipboard access is routed through `ProcessWpfClipboard`; file open/save/folder picking is routed through `ProcessWpfFileDialogService`; low-level keyboard/text/mouse/wheel input is routed through `SilkNetWpfInputService` and reaches explicit portable top-level input handlers or real WPF's internal `PortableInputEventArgs` handoff through `WpfPortableWindowActivation`; real WPF `InputManager` creates portable keyboard/mouse devices on non-Windows, skips the Windows STA construction gate outside Windows, and now promotes portable raw keyboard/text/mouse/wheel reports into routed WPF input events including the first capture/release, `ButtonBase.Click`, and `MouseWheel` activation over `PortablePresentationSource`; WPF-shaped cursor changes are routed through `SilkNetWpfCursorService`; dispatcher-style callback posting is routed through `QueuedWpfDispatcherService`; render-priority frame scheduling is routed through `DispatcherWpfRenderScheduler`; event-driven native-loop wakeups are routed through Silk.NET `IWindow.ContinueEvents()` when dispatcher/render work cannot be processed immediately on the owner thread; file-drop payloads are routed through `SilkNetWpfDragDropService`; focus-derived activation/deactivation and external file drops are routed through `SilkNetWpfWindowEventService`; monitor bounds, primary identity, and DPI scale are routed through `SilkNetWpfMonitorService`; one-shot/repeating timers are routed through `ThreadPoolWpfTimerService`; non-Windows `MediaContext` clock reads use `Stopwatch`; non-Windows `MediaSystem` startup/shutdown skips MILCore partition and DUCE transport work while preserving lifetime bookkeeping; non-Windows `HwndTarget` type loading skips Win32 message registration and construction fails fast; non-Windows stylus/touch probing is disabled until a portable tablet/input abstraction exists; and non-Windows `MediaContextNotificationWindow` currently no-ops the Windows hidden-HWND DUCE notification hook while the portable ProGPU/Silk.NET channel notification source is still pending.
- Windows-only compatibility: retain a Windows implementation behind the same abstraction where behavior cannot be portable.

No new direct Win32 calls should be added to the ProGPU lane.
