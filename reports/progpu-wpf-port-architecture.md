# ProGPU WPF Port Architecture

## Current WPF Rendering Boundary

WPF managed rendering persists content in `RenderData`, `Drawing`, `DrawingVisual`, and `Visual` objects. Those objects are marshalled into `DUCE.Channel` command streams and consumed by MIL/native rendering. The Windows-only seams include:

- `DUCE.Channel`, `MILCMD`, and `MilCoreApi` P/Invoke calls.
- `HwndSource`/`HwndTarget` and Win32 message handling.
- D3D, WIC, DWrite, tablet, input, clipboard, drag/drop, and monitor/DPI APIs.

## ProGPU Replacement Boundary

ProGPU replaces MIL/D3D composition with:

- `ProGPU.Backend.WgpuContext` for WebGPU device, queue, surface, and swapchain management.
- `ProGPU.Scene.Compositor` for retained visual rendering.
- `ProGPU.Scene.DrawingContext` and `RenderCommand` for recorded drawing operations.
- Silk.NET windowing for cross-platform surface ownership and event pumping.

## First Port Lane

`src/ProGPU.Wpf` is the initial bridge:

- `ProGpuWpfCompositionTarget` owns a ProGPU context/compositor pair and renders a root ProGPU drawing visual.
- `ProGpuWpfDrawingFrame` prepares the retained ProGPU root visual once per frame, exposes drawing-context factories that can create multiple WPF-shaped drawing-context wrappers over the same command buffer, and tracks owner/count diagnostics for provider-created contexts.
- `WpfRenderDataSinkProviderBridge` is the transition adapter that can install an active frame's drawing-context factory into WPF's internal render-data sink provider once the provider exists in the loaded `PresentationCore` identity.
- `ProGpuWpfWindowHost` owns a Silk.NET window and forwards each frame to WPF-shaped drawing callbacks.
- `IWpfCompositionCommandSink` is the replacement seam for redirecting WPF managed drawing operations away from `RenderData.WriteDataRecord` and into a backend implementation.
- `ProGpuCompositionCommandSink` is the first sink implementation and forwards WPF-shaped draw calls to the ProGPU shim drawing context.
- `WpfCompositionDrawingContext` is the first source-level adapter for managed draw calls that can bypass MIL byte serialization and call `IWpfCompositionCommandSink` directly while preserving WPF push/pop balancing semantics and reporting unsupported source-level operations.
- `IWpfGeneratedRenderDataDrawingContext` and `WpfRenderDataInstructionRedirectionCatalog` define the current source-level generated-method contract and metadata gate. Tests compare the catalog to WPF's `Resource.xml` render-data instruction definitions so generator-surface drift is caught before the real `renderdata.cs` branch is changed.
- `IRenderDataDrawingContextSink` is now present in the real WPF `PresentationCore` source tree. `RenderDataDrawingContext` can be constructed with that sink, and both the render-data generator and checked-in generated `RenderDataDrawingContext.cs` now redirect to the sink before MIL byte-record serialization while keeping the existing Windows/MIL path as the default. `DrawingContextRenderDataSink` maps the sink surface back onto WPF's managed `DrawingContext`, and `RenderDataDrawingContextSinkProvider.PushDrawingContextFactory(...)` plus `VisualDrawingContext.Create` route `DrawingVisual.RenderOpen()` and `UIElement.RenderOpen()` through a scoped drawing-context factory for future ProGPU composition targets. Provider registrations use a nested scope stack so nested frames or out-of-order disposal restore the nearest still-active drawing route rather than blindly replacing the current route.
- `WpfMilRenderDataDecoder` can decode the primitive generated WPF `RenderData` byte stream format and invoke `IWpfCompositionCommandSink`.
- `WpfReflectionResourceResolver` adapts common real-WPF-shaped dependent resources to ProGPU shim resources while the real WPF assemblies and shim assemblies still have different type identities.
- `IWpfImageSourceAdapter` is an opt-in GPU resource creation boundary for image replay. `WpfBitmapSourceImageAdapter` can copy WPF-shaped bitmap pixels through `CopyPixels(Array, int, int)`, reflect palette colors, delegate WPF/WIC-shaped pixel row conversion to ProGPU's reusable `PixelDataConverter`, and upload the resulting Pbgra32 bytes into a ProGPU-backed shim `WriteableBitmap`.
- `IWpfDrawingResourceResolver` and `WpfReflectionDrawingReplay` handle `MilDrawDrawing` for common WPF-shaped drawing resources without requiring a compile-time WPF dependency, including bounded geometry-fill replay paths for `ImageBrush`, `DrawingBrush`, and `VisualBrush` instances.
- `WpfRenderDataReflectionBridge` snapshots WPF `RenderData` private buffers and dependent-resource lists for transition replay through `WpfMilRenderDataDecoder`.
- `WpfVisualContentReflectionBridge` extracts `DrawingVisual._content` and replays `RenderData` content without taking a dependency on WPF assemblies at compile time.
- `WpfVisualTreeReflectionRenderer` recurses through `ContainerVisual.Children`, applies compatible transform/offset/clip/opacity state using the same media adaptation boundary, and records unsupported state while replaying content.
- `IWpfViewport3DCommandSink` and `WpfViewport3DReflectionBridge` provide the first WPF 3D transition path. The bridge reflects WPF-shaped `Viewport3DVisual`, projection cameras, `ModelVisual3D`, `Model3DGroup`, `GeometryModel3D`, `MeshGeometry3D`, and common material/light data into ProGPU's `Mesh3D` compositor extension payload.
- `WpfViewport3DTextureCache` is owned by `ProGpuWpfCompositionTarget` and reuses offscreen color/MSAA/depth textures for reflected Viewport3D content, disposing unused entries after each replay frame.
- `WpfVisualInvalidationTracker` observes common WPF-shaped change notifications by reflection and marks the ProGPU retained root dirty when source visuals/resources change.
- `IWpfRenderScheduler` and `CoalescingWpfRenderScheduler` provide the first render-request boundary between WPF-style invalidation and the Silk.NET host loop.
- `ProGpuWpfCompositionTarget.WpfImageSourceAdapter` and `ProGpuWpfWindowHost.WpfImageSourceAdapter` surface image upload for transition visual replay. The window host defaults this to `WpfBitmapSourceImageAdapter`; callers can replace it or set it to null.
- `IWpfPlatformServices` defines the first local OS abstraction boundary for non-rendering Win32 services. The default host uses `CrossPlatformWpfPlatformServices`, with `ProcessWpfLauncher` replacing simple Win32 `ShellExecute`-style URI/file launch behavior through `ProcessStartInfo.UseShellExecute`, `ProcessWpfClipboard` replacing text clipboard access through platform commands, `ProcessWpfFileDialogService` replacing file open/save/folder picker calls through platform commands, `SilkNetWpfInputService` replacing low-level Win32 keyboard/mouse message intake through Silk.NET input, `SilkNetWpfCursorService` replacing Win32 cursor selection through Silk.NET standard cursors, `QueuedWpfDispatcherService` replacing Win32 message-loop posting with owner-thread prioritized callback processing, `SilkNetWpfDragDropService` replacing the first external file-drop payload intake through Silk.NET file-drop events, `SilkNetWpfWindowEventService` replacing low-level activation and external file-drop message intake through Silk.NET window events, `SilkNetWpfMonitorService` replacing monitor enumeration and DPI scale derivation through Silk.NET/reflected backend metadata, and `ThreadPoolWpfTimerService` replacing Win32 timer dependencies for portable one-shot/repeating timers.
- The project references `external/ProGPU/src/PresentationCore`, reusing the existing shim for `System.Windows.Media.DrawingContext`, brushes, pens, geometries, text, and bitmaps.

`ProGpuWpfCompositionTarget.ReplayVisualSubtree` and `ProGpuWpfWindowHost.WpfRootVisual` are the first integration points from WPF-shaped retained visuals into the ProGPU scene. The host replays `WpfRootVisual` before user draw callbacks and exposes `LastVisualReplayResult` so unsupported content or state is visible to callers during bring-up.

The test suite now verifies both the decoder/control-flow layer and the actual ProGPU command-recording layer by replaying decoded records through `ProGpuCompositionCommandSink` into `ProGPU.Scene.DrawingContext`.

The source-level drawing-context adapter is a prototype for the next generator migration. It should become the branch taken by generated `RenderDataDrawingContext` methods once real WPF `PresentationCore` is compiled in the ProGPU lane. Until then, it gives the port a testable managed draw-call path that does not allocate `RenderData`, dependent-resource token tables, or DUCE/MIL records. The adapter reports applied and unsupported source operations; generated no-op draw guards return before issuing sink commands or counting animation state when required resources are null. `DrawDrawing` reuses the transition drawing replay helper and returns applied/skipped/unsupported status, while the generated-method contract exposes the expected void shape for future generator calls. Unsupported video draws and effect push scopes are explicit, with effect scopes preserving nesting so generated pop behavior remains valid. Null generated clip, transform, and opacity-mask resources now push no-op scopes so generated pop and close-time auto-balance behavior stays aligned with WPF transition replay. Dynamic frozen guideline sets with one or two Y guidelines route through the same `PushGuidelineY1`/`PushGuidelineY2` shapes that generated WPF uses, and other dynamic frozen sets can pass through `PushGuidelineSet(object?)`; the ProGPU sink applies basic X/Y-coordinate snapping for supported axis-aligned primitive commands. Generated animated overload shapes and animated MIL records now forward their base values and count non-null animation clocks or nonzero animation handles as unsupported animation state until ProGPU has an animation resource/timeline path.

Direct ProGPU installation of the real WPF sink remains an assembly-boundary decision. `PresentationCore` is strong-named and exposes internals to strong-named friend assemblies; the ProGPU submodule assemblies are now also strong-name signed with public key token `c29c9752855ee183`, but the current `ProGPU.Wpf` bridge still uses the ProGPU shim `PresentationCore` type identity. Until those identities are unified or an explicit signed friend assembly is introduced, sink registration stays as an internal WPF hook that can be activated by the eventual in-assembly or friend-assembly ProGPU target. The current preferred activation path is a ProGPU-backed WPF `DrawingContext`, installed through `PushDrawingContextFactory(...)`, because that keeps generated rendering tied to the managed WPF drawing abstraction rather than a ProGPU-specific interface. `WpfRenderDataSinkProviderBridge` makes this activation explicit and testable: it probes for the internal provider by name, creates the provider's typed factory delegate only when the loaded types are assignable, and fails closed against the current shim where the provider is absent.

`ProGpuWpfCompositionTarget.BeginDrawingFrame`, `OpenCompositionDrawingContext`, and `CreateCompositionDrawingContext` connect that source-level adapter to the retained ProGPU root visual. The frame object is the bridge shape intended for WPF provider installation: it clears the retained root once, then creates per-visual/per-render-open drawing contexts that append into the same ProGPU command buffer while tracking owner/count diagnostics. Direct composition-target replay also begins a frame, attempts `TryRegisterRenderDataSinkProvider(...)`, and opens drawing contexts from that frame before replaying a WPF-shaped subtree. `ProGpuWpfWindowHost` registers the active frame with `WpfRenderDataSinkProviderBridge` for the duration of visual replay, source-level WPF drawing, raw drawing, and frame render events. `ProGpuWpfWindowHost.WpfDraw` runs a `WpfCompositionDrawingContext` callback during each Silk.NET frame after reflected root visual replay and before the lower-level raw ProGPU `Draw`/`Render` callbacks. `ProGpuWpfFrameEventArgs.DrawingFrame` exposes the active frame to callbacks, and `LastSourceDrawingResult` exposes applied and unsupported source-operation counts from the callback.

`ProGpuCompositionCommandSink` records primitive line, rectangle, rounded-rectangle, ellipse, geometry, bitmap image, glyph-run, formatted-text, opacity, clip, opacity-mask, and Viewport3D operations as native ProGPU commands carrying the active WPF transform where applicable. It bypasses the shim `Geometry.Draw` and `DrawingContext.PushClip` fallbacks when WPF geometry can be converted to a ProGPU vector path. Geometry draws record native `DrawPath` commands, preserving path figures, WPF arc metadata, and `PathSegment.IsSmoothJoin` for the compositor. Transformed arcs are kept as native ProGPU `ArcSegment` values through `ProGPU.Vector.ArcSegmentGeometry.TryTransformArcSegment`, including translation, positive scale/rotation fast paths, arbitrary affine shear, and orientation-reversing transforms that flip sweep direction; only truly degenerate arcs fall back to endpoint lines. Primitive line, rectangle, rounded-rectangle, and ellipse commands apply active dynamic `GuidelineSet`, `PushGuidelineY1`, and `PushGuidelineY2` snapping before command recording when the current transform is axis-aligned; `PushGuidelineY2` preserves the driven-edge offset. WPF-shaped `LineJoin`, `MiterLimit`, and `PenLineCap` values are copied through the shim `Pen` into native ProGPU vector pens on recorded commands, with miter limits clamped to WPF's effective minimum of `1.0`. ProGPU vector path stroking now emits native filled triangle geometry for miter, bevel, and round joins between adjacent line, quadratic Bezier, cubic Bezier, and arc segments using endpoint tangents, falls back from miter to bevel when the miter limit is exceeded, suppresses hard join filler geometry when the incoming path segment carries `IsSmoothJoin`, emits native square, round, or triangle cap geometry for open line, quadratic Bezier, cubic Bezier, and arc paths using endpoint tangents, and emits shader-native arc stroke strips by passing transformed ellipse center/axis vectors to vector WGSL for parametric vertex/tangent evaluation instead of flattening valid arcs to line segments. Positive and dot-style dash-array pens replay straight `DrawLine` calls and rectangle outlines as native line segment commands in local coordinates, preserving active transforms and continuous rectangle dash phase. Dashed path-compatible geometries now keep WPF `ArcSegment` spans native by splitting visible dash intervals with `ProGPU.Vector.ArcSegmentGeometry.TryCreateSubArcSegment` and recording those spans as `DrawPath` arc commands; dash distance lookup still uses a bounded arc-length table, but rendering stays on the ProGPU arc shader instead of cubic or line fallback geometry. Positive dash-array rounded-rectangle, ellipse, and non-arc Bezier path outlines still use local line-segment approximation before dash emission, and filled dashed primitives or geometries emit the fill before the segmented outline. Filled dashed combined geometries keep their native combined fill and emit operand-boundary dashed outline segments with unsupported-fidelity diagnostics until exact boolean-result dashed outlines are implemented. Zero-length drawn dash entries become one-thickness transition dot segments. Transition-emitted line segments support WPF `Square` caps by extending endpoints by half the pen thickness, `Round` caps by emitting filled circular cap geometry, and `Triangle` caps by emitting filled triangle geometry with the apex one pen radius outward. Shim bitmap image draws record native `DrawTexture` commands. Shim-compatible glyph runs record native `DrawGlyphRun` commands with the glyph-run transform composed with the active WPF transform. Shim-compatible formatted text records native `DrawText` commands with the active WPF transform. Opacity scopes record native `PushOpacity`/`PopOpacity` commands. Clip scopes record native `PushGeometryClip`/`PopGeometryClip` commands, preserving non-rectangular clip intent. Native opacity-mask scopes carry the active WPF transform in the recorded ProGPU command. Null generated clip, transform, and opacity-mask resources are represented as no-op sink scopes so later pops preserve WPF stack semantics without emitting native rendering state. Reflected Viewport3D visuals record a `DrawExtension` Mesh3D command to render into the cached offscreen target, then a transformed `DrawTexture` command to composite that target into the 2D visual tree. Geometries that cannot produce a path and non-shim image sources still fall back to shim behavior until their managed representation is ported.

## Managed WPF Reuse Strategy

The migration should move WPF managed code in layers:

1. Keep dependency properties, Freezable, animation clocks, visual tree, layout, and drawing object model managed.
2. Redirect generated `RenderDataDrawingContext` methods from `RenderData.WriteDataRecord(MILCMD, ...)` to an in-assembly sink, route visual render-open through a scoped provider, then bridge that sink through `WpfRenderDataSinkProviderBridge`, an active `ProGpuWpfDrawingFrame`, and ProGPU-backed WPF `DrawingContext` to `IWpfCompositionCommandSink` in the ProGPU lane.
3. Use `WpfCompositionDrawingContext` as the source-level adapter for new ProGPU render targets, and keep `WpfRenderDataReflectionBridge` plus `WpfMilRenderDataDecoder` as a compatibility bridge for existing `RenderData` buffers during the transition.
4. Replace DUCE resource creation/update/release with ProGPU resource handles and command references.
5. Replace `HwndTarget` with a Silk.NET-backed target and keep WPF's `CompositionTarget` API shape.
6. Replace native helpers with platform services or pure managed implementations.
7. Fold the ProGPU shim back into the real WPF assemblies once enough native-only seams are abstracted.

The reflection bridge is a transition mechanism, not the final architecture. Once managed WPF code compiles in the port lane, the preferred path is to expose `RenderData` snapshots or redirect generated render-data writers in assembly rather than relying on private-field reflection.

Visual subtree replay currently covers `DrawingVisual` content backed by `RenderData`, `MilDrawDrawing` for common drawing resources, child traversal through `Children`, compatible transform/offset/native-primitive-draw/native-geometry-draw/native-geometry-clip/scrollable-area-clip/opacity/opacity-mask/guideline state, supported `BitmapScalingMode=NearestNeighbor`/`LowQuality`/`Linear`/`HighQuality`/`Fant` image-sampling state, supported `EdgeMode=Aliased` vector edge state, supported `TextRenderingMode=Aliased`/`Grayscale` text antialiasing state, reflected Viewport3D mesh payload compilation, and reflection adaptation for solid brushes, linear and radial gradients with large stop tables, bounded mapping/spread/invertible affine brush-coordinate transforms/color-interpolation methods, radial gradients with separate X/Y radii and gradient origins, pens, matrix/translate/scale/rotate/skew/transform-group affine transforms, line geometry, rectangle geometry, ellipse geometry, geometry groups, combined geometry, reflected path geometry, parseable path geometry, simple glyph runs, bounded `ImageBrush`, `DrawingBrush`, and `VisualBrush` geometry fills with relative/absolute viewports, relative/absolute cropped viewboxes, adaptable affine absolute and relative brush transforms, `AlignmentX`/`AlignmentY`, `Stretch=None`/`Fill`/`Uniform`/`UniformToFill`, and bounded `TileMode=Tile`/`FlipX`/`FlipY`/`FlipXY` replay, and opt-in bitmap source upload for common 32-bit, 24-bit, packed grayscale, indexed palette, 16-bit grayscale/BGR, 48/64-bit integer RGB/RGBA, non-profiled scRGB float, and non-profiled CMYK formats. Visual opacity masks use reflected bounds, render size, actual size, or finite bounds inferred from replayable self or child render-data content, including transformed content records. Reflected drawing groups report partial replay when supported children draw but unsupported siblings remain, so bring-up diagnostics do not hide missing content. Reflected geometry groups preserve their fill rule and bake child path transforms into copied figures during pure-path flattening; mixed groups containing combined geometry are folded into ProGPU union combined-path trees so path children and nested boolean content both survive native command emission. Reflected path geometry preserves figures, fill rule, line/polyline, quadratic/polyquadratic bezier, cubic/polycubic bezier, and arc segment metadata. Reflected combined geometry preserves WPF `Union`, `Intersect`, `Xor`, and `Exclude` as ProGPU combined vector paths using operation ids `2`, `1`, `3`, and `0` respectively; `Exclude` maps to ProGPU difference `A - B`. Geometry-owned transformed arcs, transformed arc clips, and transformed arcs inside flattened geometry groups stay native ProGPU arc segments via the ProGPU affine arc transform helper, falling back to lines only for degenerate arcs. Visual effects, legacy bitmap effects, cache mode, unrecognized bitmap scaling modes, ClearType, and text hinting mode are counted as unsupported visual state during transition replay instead of being silently ignored.

The Viewport3D reflection path is intentionally a transition bridge. It does not compile WPF 3D types directly; it reflects WPF-shaped objects and creates ProGPU `Viewport3DCompilationPayload` instances. It supports perspective and orthographic projection-camera matrices, mesh positions, indices, normals or generated normals, model transforms, front/back materials, diffuse/specular/material-group colors, and simple directional/ambient light hints. It does not yet implement WPF 3D hit testing, `Viewport2DVisual3D`, texture brushes as mesh materials, animation clocks, camera controller behavior, exact WPF lighting/material semantics, or retained geometry-version invalidation once the real WPF assemblies are compiled into the port lane.

Transition invalidation now has a reflection tracker for source objects that expose `Changed`, `Invalidated`, `INotifyPropertyChanged`, or `INotifyCollectionChanged`. The tracker follows common visual/resource references such as children, content, drawing collections, brushes, pens, geometries, path figures/segments/points, combined-geometry operands, gradient stops, image sources, glyph runs, transforms, clips, opacity masks, guideline sets, and Viewport3D camera/model/material/mesh collections. `ProGpuWpfCompositionTarget` attaches this tracker during visual replay and invalidates the ProGPU root visual when the source graph changes.

Render requests are coalesced through `IWpfRenderScheduler`. `ProGpuWpfWindowHost` requests a render when the root visual changes, the Silk.NET surface resizes, the target loads, or the tracked WPF source graph invalidates. This is not yet full WPF `MediaContext`: dirty-region calculation, render priority integration, event-loop wakeups, animation ticks, and in-assembly `Visual` change flags still need to be ported.

Glyph-run adaptation preserves WPF glyph indices, baseline origin, font rendering size, advance widths, optional glyph offsets, and reflected `GlyphTypeface.StyleSimulations` bold/italic flags, then resolves the closest available ProGPU `TtfFont` from a reflected local `GlyphTypeface.FontUri`/font file path when available, by WPF glyph typeface family name when not, or by platform fallback as a last resort. Successfully loaded font files are cached by path so repeated glyph-run replay does not reload the same font data. Once adapted, the composition sink records the run as a native ProGPU `DrawGlyphRun` command carrying the active transform and style-simulation flags.

This glyph path is an intermediate replay bridge. It does not replace WPF text formatting, LineServices, DWrite shaping, bidirectional text handling, font fallback chains, caret stops, or full glyph typeface simulation and fallback identity beyond the current bold/italic simulation flags. The in-tree portable text boundary now source-shares ProGPU's basic one-scalar-to-one-glyph analyzer fallback with cluster maps and metric-derived advances, but it deliberately does not implement OpenType feature shaping, ligatures, contextual substitution, mark positioning, or complex script handling. Those concerns still need a deliberate text stack decision: either route WPF formatted text through ProGPU's text APIs or introduce a cross-platform shaping layer before emitting ProGPU glyph commands.

The root `PresentationCore` and `PresentationFramework` build graphs now succeed on macOS after the SDK/build-tool bring-up changes, the non-Windows `MS.Internal.Text.TextInterface` boundary documented in `progpu-wpf-text-stack.md`, and Windows-only guards around every managed-graph `DirectWriteForwarder.vcxproj` reference in `PresentationCore`, `ReachFramework`, and `PresentationFramework`. The text boundary preserves the managed shape WPF expects from DirectWriteForwarder and now includes source-shared ProGPU helpers for file-backed SFNT metadata, cmap glyph mapping, metrics, embedding rights, GSUB/GPOS/GDEF table access, simple glyph mapping/placement, and glyph-ID-preserving TrueType subset writing. Direct `ProGPU.Text` project references from root WPF assemblies are still deferred while the TFM/project graph is split, so focused ProGPU text helpers are source-shared as internal WPF implementation details. This confirms the next in-assembly port boundary: replace the source-shared simple analyzer fallback, compact/remapping subsetting gaps, and LineServices seams with real cross-platform implementations before claiming formatted text fidelity, then move from buildable managed assemblies toward a Silk.NET-backed `CompositionTarget`/windowing path.

Image replay is deliberately explicit because it allocates GPU textures and must respect the active ProGPU context. The low-level reflection resolver uses exact ProGPU shim identity unless an `IWpfImageSourceAdapter` is supplied. The composition target exposes that adapter for replay calls, and the Silk.NET window host enables `WpfBitmapSourceImageAdapter` by default so WPF-shaped retained visuals can draw common bitmap content during bring-up. Once an image has shim `BitmapSource` identity, the sink records it as a transformed native `DrawTexture` command. The first adapter now keeps WPF reflection and `WriteableBitmap` construction in the bridge, while ProGPU.Backend owns reusable conversion for `Pbgra32`, premultiplied/straight BGRA/BGR formats, packed grayscale, indexed palette, 16-bit grayscale/BGR, 48/64-bit integer RGB/RGBA, non-profiled scRGB float, and non-profiled CMYK rows. Full WIC replacement still needs platform codecs, metadata/color-profile policy, caching, invalidation, download state, texture-backed bitmap sources, and lifetime management.

Shader effects should be ProGPU-native rather than managed pixel loops. ProGPU.Scene now includes a `WpfShaderEffect` compositor extension with a WebGPU/WGSL execution contract for WPF-style `c#` constants packed as 32 `vec4<f32>` registers, bounds/texture-size uniforms, a fixed 16-slot sampler-register bank, transparent fallback textures for unbound samplers, explicit compositor-compatible pipeline layouts, cached native texture bind groups, and cached render pipelines. Shader WGSL can use `wpf_sample_source(uv)` for sampler register 0 or `wpf_sample_register(registerIndex, uv)` for WPF sampler-register inputs. The WPF bridge can reflect WPF-shaped `BlurEffect` and `DropShadowEffect` objects into ProGPU-native `BlurEffect`/`DropShadowEffect` descriptors and the Silk.NET host now replays `WpfRootVisual` through a retained ProGPU scene layer. `ProGpuRetainedCompositionCommandSink` creates bounded retained drawing visuals for supported visual-effect scopes, localizes effect content into the inferred bounds, and lets ProGPU's native `Visual.Effect` path perform the offscreen blur/drop-shadow work. The direct flat replay path still reports visual effects as unsupported because it has no retained visual boundary. The remaining WPF work is WPF `ShaderEffect` descriptor mapping, generated `PushEffect` scope mapping where enough resource data is available, and translation or registry replacement for legacy Direct3D pixel-shader bytecode, because WebGPU cannot execute that bytecode directly.

Bitmap image sampling is now part of the transition visual-state bridge. Reflected `BitmapScalingMode=NearestNeighbor` pushes a scoped nearest-neighbor texture-sampling mode into `ProGpuCompositionCommandSink`; `LowQuality`, `Linear`, `Unspecified`, `Default`, and `Auto` use linear sampling, matching WPF's native aliasing of `LowQuality` and `Linear` to the same interpolation mode; and `HighQuality`/`Fant` use shader-side cubic texture sampling. Native ProGPU `DrawTexture` commands carry that sampling mode, and the compositor includes it in texture bind-group cache keys so nearest, linear, and cubic texture draws do not alias for the same texture. The same supported modes are replayed for WPF-shaped `DrawingGroup.BitmapScalingMode`; unknown bitmap-scaling values report partial replay when supported children still draw. Reflected visual and drawing-group `EdgeMode=Aliased` pushes a scoped vector edge state into `ProGpuCompositionCommandSink`; native ProGPU vector commands carry `RenderCommand.IsEdgeAliased`, the compositor encodes it into the existing `ShapeType` vertex channel, and the vector shader thresholds primitive, stroke, curve, and path-atlas coverage instead of smoothing it. Reflected visual and drawing-group `TextRenderingMode=Aliased`/`Grayscale` pushes scoped text antialiasing state into `ProGpuCompositionCommandSink`; native ProGPU text commands carry `RenderCommand.IsTextAliased`, the compositor encodes that state into the existing text flags channel, and the text shader thresholds glyph atlas alpha for aliased text while leaving grayscale text on the current smoothed glyph path. WPF-shaped `DrawingGroup.ClearTypeHint` and `TextRenderingMode=ClearType` are still surfaced as unsupported partial state instead of being silently ignored. ClearType/subpixel text rendering and text hinting remain unsupported until the text pipeline has explicit backing.

The first tile-brush transitions are intentionally bounded. WPF-shaped `GeometryDrawing` fills can replay `ImageBrush`, `DrawingBrush`, and `VisualBrush` instances when the brush uses relative or absolute viewport units, relative or absolute viewbox units, `TileMode=None`, bounded `TileMode=Tile`, bounded `FlipX`, bounded `FlipY`, or bounded `FlipXY`, `Stretch=None`, `Stretch=Fill`, `Stretch=Uniform`, or `Stretch=UniformToFill`, `AlignmentX=Left`/`Center`/`Right`, `AlignmentY=Top`/`Center`/`Bottom`, and an absent, identity, or adaptable affine `Transform`/`RelativeTransform`. Relative transforms are converted through the finite filled geometry bounds before replay. Tiled paths require finite fill geometry and cap replay expansion. ImageBrush non-full viewboxes are emitted through `IWpfCompositionCommandSink.DrawImage(..., sourceRectangle)` and ProGPU `DrawTexture.SrcRect` when the adapted image exposes pixel dimensions. DrawingBrush and VisualBrush non-full viewboxes are handled by mapping the selected source bounds into the brush viewport and pushing a transformed source-space clip before nested drawing or visual replay. Non-fill stretch aligns source content inside each tile; oversized `UniformToFill` and source-sized `None` content is clipped to the tile before replay. Flip tiling mirrors alternating tile columns and/or rows by emitting destination-space mirror transforms. All three paths clip to the adapted fill geometry and preserve brush opacity. Non-affine or unreadable transform types and advanced visual-brush cases remain unsupported and are counted as partial unsupported content when a supported stroke, nested drawing subset, or visual subtree subset can still be replayed.

Visual replay still needs richer adapters for remaining tile-brush cases including non-affine or unreadable transform types and advanced visual-brush state, platform codecs, color management and color-profile fidelity, formatted text, complex glyph/typeface identity beyond local font-file URI and bold/italic style-simulation replay, animation resources, drawing effects mapped onto ProGPU-native shader descriptors, visual masks whose finite bounds are not exposed or inferable from replayable content, WPF `ShaderEffect` lowering, non-axis-aligned/exact WPF guideline snapping fidelity, exact curve-join fidelity beyond the current endpoint tangent approximation, exact smooth-join rasterization fidelity, exact cap clipping at complex joins, exact Bezier curve dash fidelity and exact boolean-result combined-geometry dash outlines, cache state, ClearType/subpixel text rendering, text hinting, advanced 3D interop, and in-assembly retained invalidation/render scheduling. Drawing-resource opacity masks can now use reflected `DrawingGroup.Bounds` or infer finite child-content bounds, intersected with adaptable group clips, before recording native ProGPU opacity-mask scopes.

## Win32 Abstraction Strategy

Win32 usage should be split into three groups:

- Rendering/windowing: move to Silk.NET and ProGPU.
- OS services: introduce local platform abstractions for clipboard, file dialogs, input, window events, monitor/DPI, cursor, drag/drop, dispatcher posting, timers, and activation. Simple URI/file launching is routed through the cross-platform `ProcessWpfLauncher`; text clipboard access is routed through `ProcessWpfClipboard`; file open/save/folder picking is routed through `ProcessWpfFileDialogService`; low-level keyboard/text/mouse/wheel input is routed through `SilkNetWpfInputService`; WPF-shaped cursor changes are routed through `SilkNetWpfCursorService`; dispatcher-style callback posting is routed through `QueuedWpfDispatcherService`; file-drop payloads are routed through `SilkNetWpfDragDropService`; focus-derived activation/deactivation and external file drops are routed through `SilkNetWpfWindowEventService`; monitor bounds, primary identity, and DPI scale are routed through `SilkNetWpfMonitorService`; one-shot/repeating timers are routed through `ThreadPoolWpfTimerService`.
- Windows-only compatibility: retain a Windows implementation behind the same abstraction where behavior cannot be portable.

No new direct Win32 calls should be added to the ProGPU lane.
