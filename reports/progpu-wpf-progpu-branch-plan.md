# ProGPU Branch Plan for WPF Port Acceleration

## Current Branch State

The WPF superproject tracks ProGPU submodule branch `fix/render-invalidation-and-leaks`. The branch has been fast-forwarded to the latest origin commits and now includes:

- vector rendering fidelity work for WPF-style pens, caps, joins, arcs, dashed geometry, gradient brush packing, brush transforms, bitmap sampling modes, aliased vector rendering flags, native text rendering modes including ClearType, and related shader/storage-buffer changes.
- repo-level strong-name signing for ProGPU assemblies with public key token `c29c9752855ee183`.
- ProGPU-owned affine arc transformation in `ProGPU.Vector.ArcSegmentGeometry`, so WPF transformed path arcs can remain native ProGPU arc segments through translation, scale, rotation, shear, and orientation-reversing transforms.
- shader-native fixed-quad ProGPU arc stroke primitives in `ProGPU.Scene.Compositor`/`ProGPU.Backend.Shaders`, using reusable `ProGPU.Vector.ArcShaderParameters` created by `ArcSegmentGeometry.TryCreateShaderParameters(...)` to pass transformed ellipse axes and WPF/SVG sweep metadata into WGSL. The fragment shader now evaluates the arc stroke SDF directly, and the older segmented `ArcStrip` shader/vertex path has been removed, so normal WPF API arcs cannot regress to managed flattening or per-arc strip tessellation.
- exact ProGPU arc bounds for `PathAtlas` and path-op compilation, so WPF path fills and combined-geometry operations can keep native GPU arc segment records without atlas clipping from coarse sampled bounds.
- ProGPU-owned subarc and dashed-arc span construction for WPF/SVG arc spans, allowing the WPF bridge to request visible dash intervals as native `ArcSegment` commands that still render through the ProGPU arc shader instead of carrying bridge-local cubic/polyline fallback geometry.
- ProGPU-owned quadratic/cubic Bezier subdivision and dashed-span construction, allowing the WPF bridge to request visible dash intervals as native `QuadraticBezierSegment`/`CubicBezierSegment` commands that render through ProGPU's vector Bezier stroke shaders instead of bridge-local line approximation.
- ProGPU-owned primitive path construction for rectangles, rounded rectangles, and ellipses, with rounded corners and ellipse outlines represented as native arc segments so WPF dashed primitive outlines can reuse the arc dash/shader path instead of bridge-local polyline approximations.
- WPF and Skia rounded-rectangle commands now preserve separate X/Y radii in ProGPU command records, and asymmetric or per-corner cases route through native `PathGeometry` rounded-rectangle arcs. This keeps WPF elliptical rounded corners and Skia `SKRoundRect.SetRectRadii(...)` on the ProGPU vector/arc path instead of forcing bridge-side flattening.
- reusable `ProGPU.Vector.DashPattern` for WPF-compatible dash-array normalization, odd-array duplication, dash-offset state, dot-dash promotion, and straight-line dash span construction shared by line, Bezier, and arc helpers.
- native arc preservation in the ProGPU WPF/WinUI path API shims, so parsed SVG/WPF `ArcSegment` records and transformed path arcs remain `ProGPU.Vector.ArcSegment` values that feed the existing vector arc shader instead of being replaced by endpoint line placeholders. The WPF `PresentationCore` path shim now preserves original path figures and carries `Geometry.Transform` as a native `DrawPath` command transform, letting ProGPU's path atlas and fixed-quad arc shader own transformed-arc evaluation instead of baking transformed points in managed shim code.
- native geometry-clip preservation in the ProGPU WPF `DrawingContext.PushClip(Geometry)` shim, so path-compatible WPF clips record `PushGeometryClip`/`PopGeometryClip` commands with composed geometry and drawing transforms instead of degrading non-rectangular clips to axis-aligned bounds rectangles.
- opacity-neutral native mask compilation in `ProGPU.Scene.Compositor`, so geometry clip masks and opacity mask brushes are rendered into mask textures without inheriting the current draw opacity. The draw content still receives active opacity once through the normal draw path, avoiding double opacity application for WPF `PushOpacity(...); PushClip(...)` and related mask scopes.
- four-corner transformed rectangular clip bounds in `ProGPU.Scene.Compositor`, so WPF visual clips, scrollable-area clips, and unsupported-geometry rectangular fallbacks use conservative native scissor bounds under rotation or shear instead of relying on a two-corner managed workaround.
- reusable `ProGPU.Vector.PathGeometry.CreateTransformed(...)` and shim-level WPF `CombinedGeometry`, so WPF combined path draws/clips can stay native ProGPU path-op geometry while child transforms preserve arc metadata in the vector layer instead of duplicating transform code in the WPF bridge.
- reusable `ProGPU.Vector.PathGeometry.TryGetBounds(...)` plus shim-level WPF `LineGeometry`, `RectangleGeometry`, `EllipseGeometry`, and `GeometryGroup`, so primitive WPF geometry clips/draws use native ProGPU path and arc records. WPF `PathFigure.IsFilled=false` figures are now excluded from fill commands while still participating in stroke commands, addressing the ProGPU PR #17 review feedback without a managed bridge-side workaround.
- native WPF-compatible path fill/stroke semantics in ProGPU: `ProGPU.Vector.PathGeometry.FillRule` is written into the GPU path-record ABI and evaluated by the path rasterizer and path-op shaders as `EvenOdd` or `Nonzero`; WPF and WinUI path shims plus WPF `GeometryGroup` forward their fill rules; and per-segment `IsStroked` is preserved from WPF `StreamGeometryContext` into ProGPU segments so the compositor can skip non-stroked stroke spans while keeping them in fill geometry.
- Skia and GDI-compatible path shims now reuse those native path semantics: `SKPath.FillType` and `GraphicsPath.FillMode` map onto `PathGeometry.FillRule`, `SKPath.Bounds` uses arc-aware `PathGeometry.TryGetBounds(...)`, full-circle `GraphicsPath.AddArc(...)` sweeps split into native semicircle arcs instead of creating degenerate coincident-endpoint arcs, and `SKPath.Transform(...)` preserves native `ArcSegment` records through ProGPU's affine arc-transform helper instead of only moving arc endpoints. `SKPath.AddPath(...)` now deep-copies native segments so later transforms do not mutate source paths, counter-clockwise `SKPath.AddRoundRect(...)` walks the perimeter with native corner arcs instead of crossing through the rounded rectangle interior, and `SKCanvas` now preserves Skia-compatible save-layer restore/opacity semantics plus transformed rectangle/path clip commands that replay through ProGPU's native clip pipeline.
- Skia-compatible bitmap/image shims now preserve installed bitmap row stride, copy only active pixels instead of padding, normalize BGRA bitmap rows before RGBA texture upload, clip negative or partially out-of-bounds `SKImage.ReadPixels(...)` source rectangles into the destination, distinguish owned images created from bitmaps/surface snapshots from borrowed texture wrappers for deterministic texture disposal, decode `SKCodec` encoded image data into requested RGBA/BGRA bitmap layouts, and honor `SKPaint.Color.A` on `SKCanvas.DrawImage(...)` through native ProGPU opacity scopes instead of CPU-side image rewriting.
- System.Drawing-compatible bitmap shims now validate `Bitmap.LockBits(...)` rectangles before GPU readback and unsafe row-pointer copies, reject non-positive, negative-origin, and overhanging regions instead of reading outside the bitmap buffer, preserve `ImageLockMode.ReadOnly` by skipping unlock writeback, avoid flushing recorded GPU draws from bitmap finalizers, and preserve existing texture pixels when flushing recorded draws over already-defined bitmap contents. This addresses the ProGPU PR #17 bitmap lock/finalizer/flush review cluster in the backend.
- System.Drawing-compatible image draws now preserve the full active `Graphics` affine transform by recording texture commands with local destination rectangles plus command transforms, so WPF/GDI-shaped rotated and sheared image content can stay on the native texture path instead of relying on managed quad pre-transforms.
- Skia and System.Drawing-compatible clear operations now use native `GpuBlendMode.Src` around full-target clear rectangles, preserving source clear semantics for transparent and partial-alpha clears without managed WPF-side pixel rewriting. The headless test graph excludes transitive Microsoft `System.Drawing.Common` package assets so signed ProGPU drawing-shim tests consistently bind to the local shim assembly.
- bounded native path-op output writes in `PathOpGeometrySolver`: the output segment buffer is sized to the shader split capacity, the WGSL append path guards writes after the atomic reservation, and the finalizer clamps the record count. This addresses the ProGPU PR #17 path-op overflow review item and keeps WPF combined geometry reliable on the GPU boolean path.
- deferred native resource cleanup now releases queued bind-group layouts, pipeline layouts, render pipelines, compute pipelines, and shader modules, addressing the ProGPU PR #17 queued pipeline/shader leak review item in the backend rather than relying on compositor-side workarounds.
- reusable `ProGPU.Text.SfntFontFace` metadata/table/cmap/glyph-metric APIs plus `FontApi` updates for TTC face enumeration, localized name strings, and cross-platform system font directory discovery.
- `ProGPU.Text.TtfFont` now loads a requested TTC face index, and WPF/System.Drawing/Skia font caches carry `FontInfo.FaceIndex` with the font file path. This keeps macOS/Linux collection fonts and WPF fallback faces selectable without bridge-side font alias hacks.
- reusable `ProGPU.Text.SfntSimpleGlyphShaper` APIs for the current one-scalar-to-one-glyph portable fallback, including surrogate cluster maps, soft-hyphen/control handling, and metric-derived advance calculation.
- reusable `ProGPU.Text.SfntFontSubsetter` APIs for glyph-ID-preserving and compact glyph-remapping TrueType subset writing, including composite glyph dependency closure, composite component glyph-id rewriting, compact `glyf`/`loca`/`maxp`/`hhea`/`hmtx` rebuilding, `head` rewriting, checksum recalculation, explicit source-to-subset glyph maps, and stale glyph-indexed table removal.

## Decisions

- Keep feature work that accelerates WPF rendering fidelity in the ProGPU branch when it improves the backend model directly, instead of compensating in the WPF bridge.
- Keep WPF arc semantics in ProGPU vector primitives. The WPF bridge may adapt WPF types, but affine arc math, sweep flipping, and shader-rasterized arc records belong in `ProGPU.Vector`/`ProGPU.Scene`.
- Preserve API-level rounded-rectangle radii before they reach the bridge. WPF `radiusX`/`radiusY` and Skia per-corner radii should remain native ProGPU command/path data, with only uniform scalar cases using the compositor's fast rounded-rect primitive path.
- Keep WPF/WinUI path API shims from erasing arcs before rendering. Parsed `ArcSegment` values should stay native ProGPU arcs, and WPF `Geometry.Transform` should be passed as command transform metadata so ProGPU owns affine arc evaluation. Degenerate arcs may fall back only inside the ProGPU vector layer where shader parameters cannot be produced.
- Prefer fixed-quad shader primitives for WPF-compatible arc strokes. CPU flattening should be limited to degenerate arcs that cannot produce valid shader parameters; parametric strip tessellation should not be reintroduced as a WPF bridge workaround.
- Preserve WPF clip geometry as ProGPU geometry masks whenever the source geometry can be represented as a ProGPU vector path. Rectangular fallback is acceptable only for unsupported geometry forms, and rotated/sheared fallback bounds must still include all transformed corners.
- Keep WPF-specific type adaptation in `src/ProGPU.Wpf` until the real WPF `PresentationCore` and ProGPU shim type identities are unified.
- Prefer adding reusable ProGPU primitives for WPF concepts that also benefit other frontends: exact path stroking, gradient tables, texture sampling modes, text flags, mesh extensions, image effects, and retained resource lifetime helpers.
- Use signed ProGPU assemblies for direct references from strong-named WPF assemblies when the TFM/project graph is compatible. Until then, source-share small ProGPU-owned helpers only when they remain internal to WPF and avoid exposing ProGPU namespaces as WPF public API.

## ProGPU Features to Implement Next

- Text: build on the native `TextRenderingMode`/ClearType shader path plus the reusable SFNT, simple shaper, and subsetter helpers by adding richer OpenType layout table APIs, full glyph shaping hooks, fallback chains, CFF subsetting, cmap/name pruning, and WPF text hinting/ClearTypeHint policy so WPF `PortableTextInterface` can delegate more of the remaining text stack instead of carrying compatibility code. The compact glyph-remapping TrueType subsetter now exists in ProGPU; WPF should adopt it only once its embedding path can consume the returned glyph map.
- Geometry: move remaining WPF fidelity gaps into ProGPU vector code, including backend-owned dashed/stroked path commands for boolean-result outlines, non-axis-aligned guideline snapping policy, robust cap clipping at complex joins, remaining Skia/GDI path conformance cases that can feed WPF-compatible tooling paths, and remaining non-path geometry clip forms beyond path-compatible, primitive, grouped, and combined geometry that should become native masks instead of bridge-side bounds fallbacks.
- Brushes: keep expanding ProGPU brush ABI and shaders for WPF brush semantics, including more tile-brush transform cases, color-profile policy, and any remaining gradient interpolation/spread edge cases.
- Images: build on `PixelDataBuffer`/`Pbgra32PixelBuffer`, `GpuTexture.WritePbgra32SubRect(...)`, and the row-aware Skia-compatible bitmap/image shims with ProGPU image codec, color-management, cache, source-rect upload, mip/sampling policy, and texture-backed bitmap seams so WPF bitmap sources can move away from reflection-based `CopyPixels` transition upload and toward backend-owned image resources.
- Effects: continue mapping WPF effect resources onto ProGPU-native shader/compute/render pipelines. Visual `BlurEffect` and `DropShadowEffect` descriptors can now flow through retained ProGPU host replay, registered WPF `ShaderEffect` replacements can now lower to visual-level `ProGPU.Scene.WpfShaderEffect` descriptors that run WGSL over the retained visual's offscreen source through native WebGPU with WPF sampler-register mapping and active mask binding, ShaderToy/WGSL extension draws now have native active-mask and opacity propagation, simple image effects now have explicit native mask binding, source/object generated `PushEffect` can lower supported context-bound legacy bitmap effects to native retained effect scopes, and supported `DrawingGroup` effects can now wrap child drawing replay in native retained effect scopes. Remaining WPF-facing work is non-emulatable legacy bitmap effects, non-context `BitmapEffectInput`, non-implicit sampler brush/texture inputs, WebGPU device-limit strategy for the rare all-16-sampler-register plus active-mask case, and legacy Direct3D pixel-shader bytecode import/translation so existing WPF HLSL effects can populate the native ProGPU shader descriptor automatically. Avoid managed CPU shader emulation.
- Composition: build on retained `ChangeVersion` counters, effect render cache keys, reflected WPF source version polling, dispatcher/timer render scheduling, and the first host-level frame-state gate with dirty-region policy and full MediaContext integration so WPF `Freezable`/visual/effect invalidation can skip unchanged retained branches without replaying the full reflected tree. Keep native offscreen effect and layer rendering version-stable by using render-only transform overrides rather than mutating retained visual properties during composition.
- Windowing: keep Silk.NET surface and input abstractions in ProGPU reusable enough for WPF's eventual `CompositionTarget` replacement, including resize, DPI, activation, file-drop, cursor, timer, dispatcher scheduling, and render wakeup hooks.
- WPF command conformance: add ProGPU-side fixtures for every generated WPF render-data instruction that reaches `IWpfCompositionCommandSink`, so unsupported command state is tracked in ProGPU tests before WPF bridge code grows new compatibility branches.

## WPF Integration Follow-Ups

- Replace the local `PortableTextInterface` text stack with signed `ProGPU.Text` services incrementally: face-offset/table/cmap/glyph-metric discovery, the simple one-scalar-to-one-glyph fallback, and glyph-ID-preserving TrueType subsetting now use ProGPU-owned source-shared helpers. ProGPU also owns compact glyph-remapping TrueType subsetting, but WPF `GlyphTypeface.ComputeSubset` should remain glyph-ID-preserving until the embedding layer can carry the returned source-to-subset glyph map. Full shaping, fallback-chain policy, and CFF subsetting remain open text work.
- Use the portable WPF MCG path before editing generated render-data files by hand: `mcg.proj` can now run `Resources.rsp` and `Elements.rsp` through the Roslyn-backed `net10.0` CSP target on non-Windows, and the Elements XML serializer model is source-owned instead of regenerated by `xsd.exe`.
- Use the new object-sink render-data provider path as the immediate integration bridge for real WPF `PresentationCore`: `PushObjectSinkFactory(...)` can pass real WPF media objects to ProGPU.Wpf for reflection adaptation while the shim and real WPF type identities are still separate.
- Keep `src/ProGPU.Wpf.RealPresentationCoreHarness` green as the real-provider compatibility check for `WpfRenderDataSinkProviderBridge.TryRegisterRenderDataSinkProvider(Assembly, ...)` until type identity is unified.
- Make the ProGPU-backed WPF `DrawingContext` live in the real WPF type identity or a signed friend assembly later so `RenderDataDrawingContextSinkProvider.PushDrawingContextFactory(...)` can replace the object/reflection bridge.
- Add root WPF project references to signed ProGPU assemblies only when the referenced APIs are actually used by the non-Windows WPF implementation.
- Prefer extending ProGPU's native shader/effect APIs directly for WPF compatibility gaps, including bytecode import, sampler resource binding, and shader cache keys, instead of adding managed WPF-side shader workarounds.
- Preserve shader source coordinates in ProGPU draw compilation. Partial clips should either interpolate native quad UVs/fragment coordinates from the original command rectangle or rely on the compositor scissor for transformed quads; WPF bridge code should not compensate by rewriting shader inputs.
- Keep documenting each new backend requirement here before adding WPF-side compatibility code, so durable backend fixes are preferred over short-lived bridge workarounds.
