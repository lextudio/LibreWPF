# ProGPU Branch Plan for WPF Port Acceleration

## Current Branch State

The WPF superproject tracks ProGPU submodule branch `fix/render-invalidation-and-leaks`. The branch has been fast-forwarded to the latest origin commits and now includes:

- vector rendering fidelity work for WPF-style pens, caps, joins, arcs, dashed geometry, gradient brush packing, brush transforms, bitmap sampling modes, aliased vector/text rendering flags, and related shader/storage-buffer changes.
- repo-level strong-name signing for ProGPU assemblies with public key token `c29c9752855ee183`.
- ProGPU-owned affine arc transformation in `ProGPU.Vector.ArcSegmentGeometry`, so WPF transformed path arcs can remain native ProGPU arc segments through translation, scale, rotation, shear, and orientation-reversing transforms.
- shader-native fixed-quad ProGPU arc stroke primitives in `ProGPU.Scene.Compositor`/`ProGPU.Backend.Shaders`, using reusable `ProGPU.Vector.ArcShaderParameters` created by `ArcSegmentGeometry.TryCreateShaderParameters(...)` to pass transformed ellipse axes and WPF/SVG sweep metadata into WGSL. The fragment shader now evaluates the arc stroke SDF directly, so normal WPF API arcs avoid managed flattening and per-arc CPU strip tessellation.
- exact ProGPU arc bounds for `PathAtlas` and path-op compilation, so WPF path fills and combined-geometry operations can keep native GPU arc segment records without atlas clipping from coarse sampled bounds.
- ProGPU-owned subarc and dashed-arc span construction for WPF/SVG arc spans, allowing the WPF bridge to request visible dash intervals as native `ArcSegment` commands that still render through the ProGPU arc shader instead of carrying bridge-local cubic/polyline fallback geometry.
- ProGPU-owned quadratic/cubic Bezier subdivision and dashed-span construction, allowing the WPF bridge to request visible dash intervals as native `QuadraticBezierSegment`/`CubicBezierSegment` commands that render through ProGPU's vector Bezier stroke shaders instead of bridge-local line approximation.
- ProGPU-owned primitive path construction for rectangles, rounded rectangles, and ellipses, with rounded corners and ellipse outlines represented as native arc segments so WPF dashed primitive outlines can reuse the arc dash/shader path instead of bridge-local polyline approximations.
- reusable `ProGPU.Vector.DashPattern` for WPF-compatible dash-array normalization, odd-array duplication, dash-offset state, dot-dash promotion, and straight-line dash span construction shared by line, Bezier, and arc helpers.
- native arc preservation in the ProGPU WPF/WinUI path API shims, so parsed SVG/WPF `ArcSegment` records and transformed path arcs remain `ProGPU.Vector.ArcSegment` values that feed the existing vector arc shader instead of being replaced by endpoint line placeholders.
- reusable `ProGPU.Text.SfntFontFace` metadata/table/cmap/glyph-metric APIs plus `FontApi` updates for TTC face enumeration, localized name strings, and cross-platform system font directory discovery.
- reusable `ProGPU.Text.SfntSimpleGlyphShaper` APIs for the current one-scalar-to-one-glyph portable fallback, including surrogate cluster maps, soft-hyphen/control handling, and metric-derived advance calculation.
- reusable `ProGPU.Text.SfntFontSubsetter` APIs for glyph-ID-preserving and compact glyph-remapping TrueType subset writing, including composite glyph dependency closure, composite component glyph-id rewriting, compact `glyf`/`loca`/`maxp`/`hhea`/`hmtx` rebuilding, `head` rewriting, checksum recalculation, explicit source-to-subset glyph maps, and stale glyph-indexed table removal.
- reusable `ProGPU.Backend.PixelDataConverter` APIs for WPF/WIC-shaped bitmap row conversion to Pbgra32, so image upload normalization does not live only in the WPF bridge.
- native `ProGPU.Scene` WPF shader-effect execution primitives: `WpfShaderEffectParams`, `DrawWpfShaderEffect(...)`, `WpfShaderEffect`, and `WpfShaderEffectExtensionPipeline` for WGSL/WebGPU effects with WPF-style constant registers, a fixed 16-slot sampler-register bank, configurable visual-source sampler register mapping for retained `Visual.Effect` usage, `wpf_sample_source(uv)` routing through the reflected source register, explicit compositor-compatible pipeline layouts, cached native bind groups/render pipelines, transparent fallback bindings for unbound samplers, and headless render-path coverage.
- retained `ProGPU.Scene.Visual.ChangeVersion` counters that advance on property invalidation, child invalidation propagation, and child collection changes without advancing during render-time dirty clearing. `ProGpuWpfCompositionTarget` exposes scene, retained-WPF, and flat-drawing version snapshots so WPF invalidation can map to native retained dirty tracking.
- Silk.NET host frame coalescing in `ProGpuWpfWindowHost` using `ProGpuWpfFrameState` snapshots of pixel size plus ProGPU scene, retained-WPF, and flat-drawing `ChangeVersion` counters to skip unchanged frames when no explicit draw callbacks are registered and no render request is pending.
- transition WPF source version polling in `WpfVisualInvalidationTracker`, reading reflected numeric `Version`, `ChangeVersion`, and `_version` values before frame-state coalescing so mutable source resources that miss events still dirty the retained ProGPU roots.
- dispatcher/timer-backed render scheduling in `DispatcherWpfRenderScheduler`, giving the Silk.NET WPF host a portable MediaContext-style render-priority scheduling boundary before full native event-loop wakeups and animation clocks are ported.
- non-mutating offscreen visual compilation for native effect/layer rendering, so `RenderOffscreen(...)` can render at padded texture origins without assigning `Visual.Offset` or advancing `ChangeVersion` during the render pass.
- ProGPU.Text source-sharing visibility so focused helpers remain public when built by `ProGPU.Text` but compile as internal when WPF links them under `PresentationCore`.
- a ProGPU-local `global.json` pinned to SDK `10.0.201` so the submodule builds consistently even when nested below WPF's .NET 11 preview SDK checkout.
- a signing regression test in `ProGPU.Tests`.

## Decisions

- Keep feature work that accelerates WPF rendering fidelity in the ProGPU branch when it improves the backend model directly, instead of compensating in the WPF bridge.
- Keep WPF arc semantics in ProGPU vector primitives. The WPF bridge may adapt WPF types, but affine arc math, sweep flipping, and shader-rasterized arc records belong in `ProGPU.Vector`/`ProGPU.Scene`.
- Keep WPF/WinUI path API shims from erasing arcs before rendering. Parsed and transformed `ArcSegment` values should stay native ProGPU arcs unless they are mathematically degenerate.
- Prefer fixed-quad shader primitives for WPF-compatible arc strokes. CPU flattening or parametric strip tessellation should remain a ProGPU fallback for degenerate or unsupported backend cases, not a WPF bridge workaround.
- Keep WPF-specific type adaptation in `src/ProGPU.Wpf` until the real WPF `PresentationCore` and ProGPU shim type identities are unified.
- Prefer adding reusable ProGPU primitives for WPF concepts that also benefit other frontends: exact path stroking, gradient tables, texture sampling modes, text flags, mesh extensions, image effects, and retained resource lifetime helpers.
- Use signed ProGPU assemblies for direct references from strong-named WPF assemblies when the TFM/project graph is compatible. Until then, source-share small ProGPU-owned helpers only when they remain internal to WPF and avoid exposing ProGPU namespaces as WPF public API.

## ProGPU Features to Implement Next

- Text: build on the reusable SFNT, simple shaper, and subsetter helpers by adding richer OpenType layout table APIs, full glyph shaping hooks, fallback chains, CFF subsetting, and cmap/name pruning so WPF `PortableTextInterface` can delegate more of the remaining text stack instead of carrying compatibility code. The compact glyph-remapping TrueType subsetter now exists in ProGPU; WPF should adopt it only once its embedding path can consume the returned glyph map.
- Geometry: move remaining WPF fidelity gaps into ProGPU vector code, including exact boolean-result dashed outlines, non-axis-aligned guideline snapping policy, and robust cap clipping at complex joins.
- Brushes: keep expanding ProGPU brush ABI and shaders for WPF brush semantics, including more tile-brush transform cases, color-profile policy, and any remaining gradient interpolation/spread edge cases.
- Images: build on `PixelDataConverter` with ProGPU image codec and color-management seams so WPF bitmap sources can move away from reflection-based `CopyPixels` transition upload and toward backend-owned image resources.
- Effects: continue mapping WPF effect resources onto ProGPU-native shader/compute/render pipelines. Visual `BlurEffect` and `DropShadowEffect` descriptors can now flow through retained ProGPU host replay, registered WPF `ShaderEffect` replacements can now lower to visual-level `ProGPU.Scene.WpfShaderEffect` descriptors that run WGSL over the retained visual's offscreen source through native WebGPU with WPF sampler-register mapping, source/object generated `PushEffect` can lower supported context-bound legacy bitmap effects to native retained effect scopes, and supported `DrawingGroup` effects can now wrap child drawing replay in native retained effect scopes. Remaining WPF-facing work is non-emulatable legacy bitmap effects, non-context `BitmapEffectInput`, non-implicit sampler brush/texture inputs, and legacy Direct3D pixel-shader bytecode import/translation so existing WPF HLSL effects can populate the native ProGPU shader descriptor automatically. Avoid managed CPU shader emulation.
- Composition: build on retained `ChangeVersion` counters, reflected WPF source version polling, dispatcher/timer render scheduling, and the first host-level frame-state gate with dirty-region policy and full MediaContext integration so WPF `Freezable`/visual invalidation can skip unchanged retained branches without replaying the full reflected tree. Keep native offscreen effect and layer rendering version-stable by using render-only transform overrides rather than mutating retained visual properties during composition.
- Windowing: keep Silk.NET surface and input abstractions in ProGPU reusable enough for WPF's eventual `CompositionTarget` replacement, including resize, DPI, activation, file-drop, cursor, timer, and dispatcher wakeup hooks.
- WPF command conformance: add ProGPU-side fixtures for every generated WPF render-data instruction that reaches `IWpfCompositionCommandSink`, so unsupported command state is tracked in ProGPU tests before WPF bridge code grows new compatibility branches.

## WPF Integration Follow-Ups

- Replace the local `PortableTextInterface` text stack with signed `ProGPU.Text` services incrementally: face-offset/table/cmap/glyph-metric discovery, the simple one-scalar-to-one-glyph fallback, and glyph-ID-preserving TrueType subsetting now use ProGPU-owned source-shared helpers. ProGPU also owns compact glyph-remapping TrueType subsetting, but WPF `GlyphTypeface.ComputeSubset` should remain glyph-ID-preserving until the embedding layer can carry the returned source-to-subset glyph map. Full shaping, fallback-chain policy, and CFF subsetting remain open text work.
- Use the portable WPF MCG path before editing generated render-data files by hand: `mcg.proj` can now run `Resources.rsp` and `Elements.rsp` through the Roslyn-backed `net10.0` CSP target on non-Windows, and the Elements XML serializer model is source-owned instead of regenerated by `xsd.exe`.
- Use the new object-sink render-data provider path as the immediate integration bridge for real WPF `PresentationCore`: `PushObjectSinkFactory(...)` can pass real WPF media objects to ProGPU.Wpf for reflection adaptation while the shim and real WPF type identities are still separate.
- Keep `src/ProGPU.Wpf.RealPresentationCoreHarness` green as the real-provider compatibility check for `WpfRenderDataSinkProviderBridge.TryRegisterRenderDataSinkProvider(Assembly, ...)` until type identity is unified.
- Make the ProGPU-backed WPF `DrawingContext` live in the real WPF type identity or a signed friend assembly later so `RenderDataDrawingContextSinkProvider.PushDrawingContextFactory(...)` can replace the object/reflection bridge.
- Add root WPF project references to signed ProGPU assemblies only when the referenced APIs are actually used by the non-Windows WPF implementation.
- Prefer extending ProGPU's native shader/effect APIs directly for WPF compatibility gaps, including bytecode import, sampler resource binding, and shader cache keys, instead of adding managed WPF-side shader workarounds.
- Keep documenting each new backend requirement here before adding WPF-side compatibility code, so durable backend fixes are preferred over short-lived bridge workarounds.
